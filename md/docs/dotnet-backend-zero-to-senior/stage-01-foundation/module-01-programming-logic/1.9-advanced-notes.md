# 1.9 — Mở rộng và đào sâu

> Nguồn: https://tiennhm.io.vn/docs/dotnet-backend-zero-to-senior/stage-01-foundation/module-01-programming-logic/1.9-advanced-notes
> Đệ quy, LINQ, pattern matching, immutability và bất biến vòng lặp — những chủ đề tiếp theo sau nền tảng logic lập trình.

> Những chủ đề nối tiếp Module 1, kèm điều kiện để đáng học tiếp. Điểm nhấn: hai trong số chúng — **LINQ** và **pattern matching** — nên học **sớm** vì bạn sẽ gặp chúng trong mọi codebase .NET hiện đại và chúng làm code ngắn hơn đáng kể. Hai cái còn lại — **đệ quy** và **bất biến vòng lặp** — hữu ích nhưng ít dùng trong code nghiệp vụ hàng ngày. Và một lời cảnh báo cụ thể về đệ quy: trong backend .NET, nó **hiếm khi là lựa chọn đúng**, vì độ sâu đệ quy không kiểm soát được sẽ gây `StackOverflowException` — một lỗi **không bắt được bằng try/catch** và giết luôn tiến trình.

## Mục tiêu bài học

Sau bài này bạn có thể:

- Biết những chủ đề tiếp theo và thứ tự nên học.
- Dùng LINQ cho các thao tác trên tập hợp.
- Dùng pattern matching thay chuỗi `if` dài.
- Biết vì sao đệ quy ít phù hợp với backend.

## Nội dung bài học

### 1.9.1 — LINQ: học sớm

**Nên học ngay sau Module 1.** Bạn sẽ gặp nó trong mọi dự án .NET.

```csharp
// Viet tay
var khachVip = new List<Customer>();
foreach (var k in danhSach)
{
    if (k.TongChiTieu > 100_000_000m)
        khachVip.Add(k);
}
khachVip.Sort((a, b) => b.TongChiTieu.CompareTo(a.TongChiTieu));

// LINQ — cung ket qua
var khachVip = danhSach
    .Where(k => k.TongChiTieu > 100_000_000m)
    .OrderByDescending(k => k.TongChiTieu)
    .ToList();
```

Năm thao tác dùng nhiều nhất:

| Thao tác | Việc làm |
|---|---|
| `Where` | Lọc theo điều kiện |
| `Select` | Biến đổi từng phần tử |
| `OrderBy` / `OrderByDescending` | Sắp xếp |
| `GroupBy` | Nhóm theo khoá |
| `Sum` / `Count` / `Average` | Tính tổng hợp |

**Cái bẫy quan trọng nhất — deferred execution:**

```csharp
var query = danhSach.Where(k => k.TongChiTieu > 100_000_000m);
danhSach.Add(new Customer { TongChiTieu = 200_000_000m });

var count = query.Count();      // TINH LAI tai day -> bao gom ca phan tu vua them
```

LINQ **không chạy ngay** khi bạn viết `Where` — nó chỉ mô tả truy vấn. Việc chạy xảy ra khi bạn duyệt kết quả hoặc gọi `ToList`, `Count`, `First`. Gọi hai lần là chạy hai lần.

```csharp
// Dung ToList() khi can ket qua CO DINH va dung nhieu lan
var khachVip = danhSach.Where(...).ToList();
```

Đây cũng là nền tảng để hiểu EF Core, vì truy vấn database dùng chính cơ chế này ([bài 13.6](../../stage-04-database-production/module-13-entity-framework-core/13.6-query-patterns.mdx)).

### 1.9.2 — Pattern matching: học sớm

```csharp
// Chuoi if dai
string XepHang(decimal tongChiTieu)
{
    if (tongChiTieu >= 500_000_000m) return "Kim cương";
    else if (tongChiTieu >= 100_000_000m) return "Vàng";
    else if (tongChiTieu >= 10_000_000m) return "Bạc";
    else return "Thường";
}

// Switch expression — ngan hon va de doc hon
string XepHang(decimal tongChiTieu) => tongChiTieu switch
{
    >= 500_000_000m => "Kim cương",
    >= 100_000_000m => "Vàng",
    >= 10_000_000m  => "Bạc",
    _               => "Thường"
};
```

Lợi ích không chỉ là ngắn hơn: trình biên dịch **cảnh báo** nếu bạn bỏ sót trường hợp với kiểu enum, điều mà chuỗi `if` không làm được.

```csharp
// Khop theo kieu va thuoc tinh
decimal TinhPhiVanChuyen(DonHang don) => don switch
{
    { GiaTri: > 1_000_000m }                  => 0,
    { KhuVuc: "HCM" or "HN" }                 => 20_000m,
    { CanNang: > 10 }                         => 50_000m,
    _                                          => 35_000m
};
```

**Lưu ý:** thứ tự các nhánh **quan trọng** — nhánh đầu tiên khớp sẽ được chọn. Đặt điều kiện hẹp nhất lên trước ([bài 1.3](1.3-conditions.mdx)).

### 1.9.3 — Đệ quy: học để hiểu, ít dùng để viết

```csharp
// De quy — dung nhung nguy hiem trong backend
decimal TinhTongCayDanhMuc(DanhMuc dm)
{
    decimal tong = dm.GiaTri;
    foreach (var con in dm.DanhMucCon)
        tong += TinhTongCayDanhMuc(con);          // goi chinh no
    return tong;
}
```

Vấn đề cụ thể: nếu dữ liệu có **vòng lặp** (A là con của B, B là con của A — chuyện xảy ra thật khi dữ liệu bị nhập sai), hàm này chạy vô hạn cho tới khi ném `StackOverflowException`.

Và đây là điểm nguy hiểm nhất: **`StackOverflowException` không bắt được bằng `try/catch`** trong .NET. Nó giết luôn tiến trình, kéo theo mọi request khác đang chạy trên cùng process.

```csharp
// Dung stack tuong minh — kiem soat duoc, va phat hien vong lap
decimal TinhTongCayDanhMuc(DanhMuc goc)
{
    decimal tong = 0;
    var daTham = new HashSet<int>();
    var stack = new Stack<DanhMuc>();
    stack.Push(goc);

    while (stack.Count > 0)
    {
        var dm = stack.Pop();

        if (!daTham.Add(dm.Id))
            throw new InvalidOperationException($"Danh mục {dm.Id} tạo vòng lặp");

        tong += dm.GiaTri;
        foreach (var con in dm.DanhMucCon)
            stack.Push(con);
    }

    return tong;
}
```

Dài hơn, nhưng nó **phát hiện được vòng lặp** và không bao giờ làm tràn stack.

Với dữ liệu cây trong database, thường tốt hơn nữa là để database làm việc đó bằng recursive CTE ([bài 12.4](../../stage-04-database-production/module-12-sql-deep-dive/12.4-advanced-queries.mdx)).

### 1.9.4 — Immutability

```csharp
// record — bat bien, so sanh theo GIA TRI
public record DiaChi(string SoNha, string Duong, string Quan, string ThanhPho);

var dc1 = new DiaChi("12", "Nguyễn Huệ", "1", "HCM");
var dc2 = new DiaChi("12", "Nguyễn Huệ", "1", "HCM");

Console.WriteLine(dc1 == dc2);          // True — so sanh gia tri

// Muon doi thi tao ban moi
var dcMoi = dc1 with { Quan = "3" };
```

Hai lợi ích thực tế: đối tượng bất biến **an toàn khi dùng đa luồng** (không ai đổi được nó giữa chừng), và code dễ suy luận hơn vì giá trị không thay đổi sau khi tạo.

Đây là nền tảng cho value object trong DDD ([bài 16.14](../../stage-05-senior-engineering/module-16-clean-architecture/16.14-advanced-notes.mdx)).

### 1.9.5 — Bất biến vòng lặp

Một công cụ tư duy để viết vòng lặp đúng: **điều gì luôn đúng ở mỗi lần lặp?**

```csharp
// Bat bien: sau vong lap thu i, "max" la gia tri lon nhat trong danhSach[0..i]
decimal max = danhSach[0];
for (int i = 1; i < danhSach.Count; i++)
{
    if (danhSach[i] > max)
        max = danhSach[i];
}
// Ket thuc: max la gia tri lon nhat toan danh sach
```

Phát biểu được bất biến nghĩa là bạn hiểu vòng lặp đang làm gì. Nó cũng giúp bắt hai lỗi phổ biến: khởi tạo sai (bắt đầu từ `i = 0` sẽ so sánh phần tử đầu với chính nó — vô hại ở đây nhưng không phải lúc nào cũng vậy) và điều kiện dừng sai (`<=` thay vì `<` gây `IndexOutOfRangeException`).

Ít dùng trong code nghiệp vụ hàng ngày, nhưng rất hữu ích khi viết thuật toán hoặc khi một vòng lặp cho kết quả sai mà bạn không hiểu vì sao.

## Bài tập áp dụng

1. **Viết lại bằng LINQ.** Lấy ba vòng lặp trong code của bạn và viết lại bằng LINQ. So sánh số dòng.

2. **Chứng minh deferred execution.** Tạo một truy vấn `Where`, thêm phần tử vào danh sách gốc, rồi gọi `Count` và giải thích kết quả.

3. **Đệ quy có vòng lặp.** Tạo dữ liệu cây có vòng lặp và chạy hàm đệ quy. Quan sát điều gì xảy ra với tiến trình.

## Tự kiểm tra

### Deferred execution trong LINQ nghĩa là gì?

Truy vấn không chạy khi bạn viết Where mà chỉ mô tả việc cần làm. Nó chạy khi bạn duyệt kết quả hoặc gọi ToList, Count, First. Nên nếu dữ liệu gốc đổi giữa chừng, kết quả cũng đổi theo, và gọi hai lần là chạy hai lần.

### Vì sao switch expression tốt hơn chuỗi if dài?

Ngắn hơn và dễ đọc hơn, nhưng quan trọng hơn là trình biên dịch cảnh báo khi bạn bỏ sót trường hợp với kiểu enum, điều mà chuỗi if không làm được.

### Vì sao thứ tự nhánh trong pattern matching quan trọng?

Vì nhánh đầu tiên khớp sẽ được chọn, nên phải đặt điều kiện hẹp nhất lên trước. Đặt điều kiện rộng trước sẽ khiến các nhánh hẹp phía sau không bao giờ được chạy.

### Vì sao đệ quy nguy hiểm trong backend .NET?

Vì nếu dữ liệu có vòng lặp hoặc quá sâu, hàm sẽ gây StackOverflowException. Lỗi này không bắt được bằng try catch trong .NET, nó giết luôn tiến trình và kéo theo mọi request khác đang chạy.

### Dùng stack tường minh hơn gì so với đệ quy?

Nó kiểm soát được độ sâu, phát hiện được vòng lặp bằng cách ghi lại những nút đã thăm, và không bao giờ làm tràn stack của tiến trình.

### Hai lợi ích thực tế của immutability là gì?

Đối tượng bất biến an toàn khi dùng đa luồng vì không ai đổi được nó giữa chừng, và code dễ suy luận hơn vì giá trị không thay đổi sau khi tạo.

## Kết luận

Ba điều đáng nhớ nhất:

1. **LINQ và pattern matching nên học ngay** — bạn gặp chúng ở mọi nơi.
2. **Deferred execution là cái bẫy lớn nhất của LINQ**, và cũng là nền tảng của EF Core.
3. **Đệ quy hiếm khi là lựa chọn đúng trong backend** — stack tường minh an toàn hơn.
