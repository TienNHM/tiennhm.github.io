# 4.12 — Ví dụ thực tế nhanh

> Nguồn: https://tiennhm.io.vn/en/docs/dotnet-backend-zero-to-senior/stage-02-csharp-professional/module-04-csharp-core/4.12-quick-real-world-example
> Hai đối tượng cùng dữ liệu nhưng so sánh ra false: hiểu reference equality, khi nào dùng record, và cái bẫy khi ghi đè Equals.

> Một bug rất hay gặp và rất khó tin khi mới gặp: hai đối tượng có **dữ liệu giống hệt nhau** nhưng `==` trả về `false`, và `list.Contains(x)` không tìm thấy dù `x` rõ ràng nằm trong danh sách. Nguyên nhân: với `class`, C# so sánh **địa chỉ trong bộ nhớ**, không so sánh nội dung. Hai đối tượng khác nhau thì luôn khác nhau, dù mọi thuộc tính đều bằng. Cách sửa đơn giản nhất là dùng **`record`** — một từ khoá thay cho hàng chục dòng code. Nhưng có một cái bẫy ít người biết: nếu tự ghi đè `Equals` mà **quên `GetHashCode`**, `Dictionary` và `HashSet` sẽ hoạt động **sai một cách im lặng** — không lỗi, chỉ là không tìm thấy thứ rõ ràng có ở đó.

## Mục tiêu bài học

Sau bài này bạn có thể:

- Giải thích vì sao hai đối tượng cùng dữ liệu lại không bằng nhau.
- Chọn giữa `class`, `record` và `struct` theo tình huống.
- Ghi đè `Equals` và `GetHashCode` đúng cách khi cần.
- Nhận ra bug do quên `GetHashCode`.

## Nội dung bài học

### 4.13.1 — Bug

```csharp
public class DiaChi
{
    public string SoNha { get; set; }
    public string Duong { get; set; }
    public string Quan { get; set; }
}

var dc1 = new DiaChi { SoNha = "12", Duong = "Nguyễn Huệ", Quan = "1" };
var dc2 = new DiaChi { SoNha = "12", Duong = "Nguyễn Huệ", Quan = "1" };

Console.WriteLine(dc1 == dc2);          // False  (!!)
Console.WriteLine(dc1.Equals(dc2));     // False  (!!)

var danhSach = new List<DiaChi> { dc1 };
Console.WriteLine(danhSach.Contains(dc2));   // False — du du lieu giong het
```

Trong code thật, bug này biểu hiện như sau:

```csharp
// Kiem tra dia chi giao hang da ton tai chua
if (!khachHang.DanhSachDiaChi.Contains(diaChiMoi))
    khachHang.DanhSachDiaChi.Add(diaChiMoi);

// Ket qua: danh sach day dia chi TRUNG NHAU
```

### 4.13.2 — Vì sao

Với `class`, C# so sánh **tham chiếu** — tức hai biến có trỏ vào **cùng một ô nhớ** hay không.

```csharp
var dc1 = new DiaChi { ... };    // tao doi tuong o dia chi A
var dc2 = new DiaChi { ... };    // tao doi tuong o dia chi B  (KHAC)

dc1 == dc2      // so sanh A voi B -> False

var dc3 = dc1;  // dc3 tro vao CUNG dia chi A
dc1 == dc3      // True
```

Mặc định này **đúng** cho phần lớn trường hợp: hai khách hàng cùng tên không phải cùng một người. Nhưng với những thứ chỉ **mang giá trị** — địa chỉ, số tiền, khoảng thời gian — thì so sánh theo nội dung mới đúng.

### 4.13.3 — Sửa bằng record

```csharp
public record DiaChi(string SoNha, string Duong, string Quan);

var dc1 = new DiaChi("12", "Nguyễn Huệ", "1");
var dc2 = new DiaChi("12", "Nguyễn Huệ", "1");

Console.WriteLine(dc1 == dc2);               // True
Console.WriteLine(danhSach.Contains(dc2));   // True
```

Một từ khoá. Trình biên dịch tự sinh `Equals`, `GetHashCode`, `ToString`, toán tử `==` và `!=`, cùng phương thức `with` để tạo bản sao có sửa đổi ([bài 4.8](4.7-records-and-value-objects.mdx)).

```csharp
var dcMoi = dc1 with { Quan = "3" };    // ban sao, chi doi Quan
```

`record` cũng **bất biến** mặc định — sau khi tạo không đổi được thuộc tính. Đây là điều bạn muốn với value object: nếu địa chỉ thay đổi thì đó là một địa chỉ **khác**, không phải cùng địa chỉ đã bị sửa.

### 4.13.4 — Cái bẫy: quên GetHashCode

Nếu vì lý do nào đó bạn không dùng được `record` và phải tự ghi đè:

```csharp
// SAI — ghi de Equals nhung QUEN GetHashCode
public class DiaChi
{
    public string SoNha { get; set; }
    public string Duong { get; set; }

    public override bool Equals(object? obj)
        => obj is DiaChi other && SoNha == other.SoNha && Duong == other.Duong;

    // GetHashCode: KHONG ghi de -> van dung mac dinh theo tham chieu
}
```

Hậu quả, và nó **rất khó chẩn đoán**:

```csharp
var tap = new HashSet<DiaChi>();
tap.Add(dc1);

Console.WriteLine(dc1.Equals(dc2));   // True
Console.WriteLine(tap.Contains(dc2)); // False  (!!)
```

`HashSet` và `Dictionary` tìm phần tử theo **hai bước**: trước hết dùng `GetHashCode` để xác định "ngăn" chứa nó, sau đó mới dùng `Equals` trong ngăn đó. Nếu `GetHashCode` khác nhau, chúng rơi vào hai ngăn khác nhau và `Equals` **không bao giờ được gọi**.

**Quy tắc bắt buộc:** ghi đè `Equals` thì **phải** ghi đè `GetHashCode`, và hai cái phải dùng **cùng bộ thuộc tính**.

```csharp
public override int GetHashCode() => HashCode.Combine(SoNha, Duong);
```

`HashCode.Combine` xử lý đúng cả trường hợp `null` và phân bố giá trị tốt — không tự viết bằng cách nhân số nguyên tố nữa.

Trình biên dịch **có** cảnh báo về việc này (CS0659), nên đừng bỏ qua cảnh báo.

### 4.13.5 — Cái bẫy thứ hai: thuộc tính thay đổi được

```csharp
// NGUY HIEM — thuoc tinh dung de bam lai doi duoc
public class DiaChi
{
    public string Duong { get; set; }      // set duoc!
    public override int GetHashCode() => HashCode.Combine(Duong);
}

var tap = new HashSet<DiaChi> { dc };
dc.Duong = "Lê Lợi";                        // doi SAU khi da them vao tap

tap.Contains(dc);        // False — du dc DANG nam trong tap!
```

Đối tượng vẫn ở trong `HashSet`, nhưng nó nằm ở ngăn tương ứng với mã băm **cũ**. Tìm theo mã băm mới không tới đúng ngăn đó.

Đây là lý do value object **phải bất biến**, và cũng là lý do `record` mặc định bất biến. Nếu dùng `class` với `Equals` tự viết, hãy đặt mọi thuộc tính là `init` hoặc `private set`.

### 4.13.6 — Chọn class, record hay struct

| | `class` | `record` | `struct` |
|---|---|---|---|
| So sánh | Tham chiếu | **Giá trị** | Giá trị |
| Lưu ở đâu | Heap | Heap | **Stack** (thường) |
| Bất biến mặc định | Không | **Có** | Không |
| Dùng cho | Thực thể có định danh | **Value object** | Giá trị nhỏ, dùng rất nhiều |

**Quy tắc chọn:**

- Có **định danh** riêng, hai đối tượng cùng dữ liệu vẫn là hai thứ khác nhau → **`class`**. Ví dụ: `Customer`, `Order`, `Lead`.
- Chỉ **mang giá trị**, cùng dữ liệu nghĩa là cùng một thứ → **`record`**. Ví dụ: `DiaChi`, `Money`, `DateRange`.
- Rất nhỏ (dưới 16 byte) và tạo rất nhiều lần → **`struct`** hoặc `readonly record struct`.

```csharp
// Thuc the — co dinh danh
public class Customer { public CustomerId Id { get; init; } /* ... */ }

// Value object — chi mang gia tri
public record Money(decimal Amount, string Currency);

// Value object nho, dung nhieu
public readonly record struct LeadId(Guid Value);
```

Dòng cuối là mẫu **strongly-typed ID**: nó vừa cho so sánh theo giá trị, vừa không cấp phát trên heap, vừa khiến trình biên dịch bắt lỗi truyền nhầm id ([bài 16.14](../../stage-05-senior-engineering/module-16-clean-architecture/16.13-advanced-notes.mdx)).

### 4.13.7 — Rà lại code của bạn

**Danh sách rà soát so sánh đối tượng**

- [ ] Lớp chỉ mang giá trị được khai báo là record.
- [ ] Không dùng Contains hay Distinct trên class chưa ghi đè Equals.
- [ ] Nếu ghi đè Equals thì cũng ghi đè GetHashCode với cùng bộ thuộc tính.
- [ ] Dùng HashCode.Combine thay vì tự viết thuật toán băm.
- [ ] Thuộc tính dùng để băm là init hoặc private set, không đổi được.
- [ ] Không bỏ qua cảnh báo CS0659 của trình biên dịch.
- [ ] Thực thể có định danh dùng class, không dùng record.
- [ ] Id của entity dùng readonly record struct.

## Bài tập áp dụng

1. **Tái hiện bug.** Tạo một `class` và kiểm tra `Contains` với hai đối tượng cùng dữ liệu. Đổi sang `record` và thử lại.

2. **Tái hiện bẫy GetHashCode.** Ghi đè `Equals` mà không ghi đè `GetHashCode`, rồi thử `HashSet.Contains`.

3. **Tái hiện bẫy thuộc tính đổi được.** Thêm đối tượng vào `HashSet`, đổi một thuộc tính dùng để băm, rồi tìm lại nó.

## Tự kiểm tra

### Vì sao hai đối tượng class cùng dữ liệu lại không bằng nhau?

Vì với class, C# so sánh tham chiếu, tức hai biến có trỏ vào cùng một ô nhớ hay không. Hai lần new tạo ra hai ô nhớ khác nhau nên luôn khác nhau, dù mọi thuộc tính đều bằng.

### record giải quyết vấn đề này thế nào?

Trình biên dịch tự sinh Equals, GetHashCode, ToString, toán tử == và phương thức with. Record cũng bất biến mặc định, đúng với ý nghĩa của value object.

### Vì sao quên GetHashCode lại gây bug khó chẩn đoán?

Vì HashSet và Dictionary tìm phần tử theo hai bước: dùng GetHashCode xác định ngăn, rồi dùng Equals trong ngăn đó. Nếu mã băm khác nhau, hai đối tượng rơi vào hai ngăn và Equals không bao giờ được gọi. Không có lỗi nào, chỉ là không tìm thấy.

### Vì sao thuộc tính dùng để băm không được thay đổi?

Vì đối tượng đã nằm ở ngăn tương ứng với mã băm cũ. Đổi thuộc tính làm mã băm đổi, nên tìm theo mã băm mới không tới đúng ngăn đó, và Contains trả về false dù đối tượng vẫn nằm trong tập.

### Quy tắc chọn giữa class, record và struct là gì?

Có định danh riêng nên hai đối tượng cùng dữ liệu vẫn khác nhau thì dùng class. Chỉ mang giá trị nên cùng dữ liệu là cùng một thứ thì dùng record. Rất nhỏ và tạo rất nhiều lần thì dùng struct hoặc readonly record struct.

### readonly record struct phù hợp cho gì?

Cho strongly-typed ID. Nó vừa so sánh theo giá trị, vừa không cấp phát trên heap, vừa khiến trình biên dịch bắt lỗi truyền nhầm id giữa các loại entity.

## Kết luận

Ba điều đáng nhớ nhất:

1. **`class` so sánh tham chiếu, `record` so sánh giá trị.** Chọn theo ý nghĩa của kiểu.
2. **Ghi đè `Equals` thì phải ghi đè `GetHashCode`** — quên là bug im lặng.
3. **Value object phải bất biến**, nếu không `HashSet` và `Dictionary` sẽ mất dấu nó.
