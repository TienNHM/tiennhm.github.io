# 13.2 — 2. DbContext và Entity Configuration

> Nguồn: https://tiennhm.io.vn/en/docs/dotnet-backend-zero-to-senior/stage-04-database-production/module-13-entity-framework-core/13.2-dbcontext-and-entity-configuration
> DbContext là Unit of Work và không thread-safe, Fluent API so với Data Annotations, value converter, owned type, và interceptor cho audit.

> `DbContext` là **Unit of Work** — nó gom mọi thay đổi và ghi chúng trong **một transaction** khi bạn gọi `SaveChanges()`. Hai đặc tính quyết định cách dùng nó: **không thread-safe** (`Task.WhenAll` trên cùng một context là exception), và **vòng đời phải ngắn** (context sống lâu tích luỹ entity và trả dữ liệu cũ). Về cấu hình mô hình, **Fluent API mạnh hơn Data Annotations** ở mọi mặt và tách cấu hình hạ tầng khỏi entity — nhưng đừng nhồi hết vào `OnModelCreating`, hãy dùng `IEntityTypeConfiguration` mỗi entity một file. Và **value converter** là công cụ bị đánh giá thấp nhất: nó cho phép domain dùng kiểu riêng mà database vẫn lưu kiểu nguyên thuỷ.

## Mục tiêu bài học

Sau bài này bạn có thể:

- Giải thích `DbContext` là Unit of Work và hệ quả của nó.
- Tổ chức cấu hình mô hình bằng `IEntityTypeConfiguration`.
- Dùng value converter cho kiểu domain.
- Dùng owned type cho value object.
- Viết interceptor cho audit thay vì override `SaveChanges`.

## Nội dung bài học

### 13.3.1 — `DbContext` là Unit of Work

```csharp
db.Customers.Add(customer);
db.Leads.Update(lead);
db.Contacts.Remove(contact);

await db.SaveChangesAsync(ct);      // MOT transaction cho ca ba
```

EF Core tự bọc `SaveChanges` trong transaction. Cả ba thay đổi cùng thành công hoặc cùng thất bại — bạn **không cần** `BeginTransaction` cho trường hợp này.

Đây là lý do một interface `IUnitOfWork` chỉ gọi `SaveChanges` thường là lớp trung gian thừa — chi tiết ở [bài 13.10](13.9-unit-of-work-and-repository-pattern.mdx) và trong bài [Unit of Work trong .NET và ABP](https://tiennhm.io.vn/blog/unit-of-work-dotnet-abp).

Cần transaction tường minh khi bạn phải **nhiều lần** `SaveChanges` trong một đơn vị công việc:

```csharp
await using var tx = await db.Database.BeginTransactionAsync(ct);

db.Customers.Add(customer);
await db.SaveChangesAsync(ct);             // can Id sinh ra

lead.ConvertedToCustomerId = customer.Id;
await db.SaveChangesAsync(ct);

await tx.CommitAsync(ct);
```

**`DbContext` không thread-safe:**

```csharp
// SAI — InvalidOperationException
var t1 = db.Customers.ToListAsync(ct);
var t2 = db.Leads.ToListAsync(ct);
await Task.WhenAll(t1, t2);
```

Đây là bẫy đã nói ở [bài 6.6](../../stage-02-csharp-professional/module-06-async-programming/6.5-task-parallel-library.mdx). Cần song song thật thì mỗi task một context từ `IDbContextFactory`.

**Vòng đời:** `Scoped` là mặc định của `AddDbContext` và gần như luôn đúng. Context sống lâu gây bốn vấn đề: bộ nhớ phình, dữ liệu cũ từ identity map, một lỗi làm hỏng toàn bộ context, và giữ connection lâu.

Ngoài request — background job, Blazor Server — dùng factory:

```csharp
builder.Services.AddDbContextFactory<CrmDbContext>(o => o.UseSqlServer(conn));

await using var db = await _factory.CreateDbContextAsync(ct);
```

### 13.3.2 — Fluent API và `IEntityTypeConfiguration`

```csharp
// SAI — moi thu trong mot ham
protected override void OnModelCreating(ModelBuilder modelBuilder)
{
    modelBuilder.Entity<Customer>().Property(c => c.Name).HasMaxLength(200);
    modelBuilder.Entity<Customer>().HasIndex(c => c.Email).IsUnique();
    // ... 400 dong nua
}
```

```csharp
// DUNG — moi entity mot file
public sealed class CustomerConfiguration : IEntityTypeConfiguration<Customer>
{
    public void Configure(EntityTypeBuilder<Customer> builder)
    {
        builder.ToTable("Customers");
        builder.HasKey(c => c.Id);

        builder.Property(c => c.Name).IsRequired().HasMaxLength(200);
        builder.Property(c => c.Email).IsRequired().HasMaxLength(256);
        builder.Property(c => c.Status).HasConversion<string>().HasMaxLength(50);
        builder.Property(c => c.RowVersion).IsRowVersion();

        builder.HasIndex(c => c.Email).IsUnique()
               .HasFilter("[IsDeleted] = 0");          // soft delete

        builder.HasIndex(c => new { c.TenantId, c.Status });

        builder.HasMany(c => c.Contacts)
               .WithOne(ct => ct.Customer)
               .HasForeignKey(ct => ct.CustomerId)
               .OnDelete(DeleteBehavior.Cascade);
    }
}
```

```csharp
protected override void OnModelCreating(ModelBuilder modelBuilder)
    => modelBuilder.ApplyConfigurationsFromAssembly(typeof(CrmDbContext).Assembly);
```

**Vì sao Fluent API thay vì Data Annotations:**

| | Data Annotations | Fluent API |
|---|---|---|
| Ở đâu | Trên entity | File cấu hình riêng |
| Entity phụ thuộc EF | **Có** | **Không** |
| Cấu hình quan hệ phức tạp | Hạn chế | **Đầy đủ** |
| Index có filter, khoá phức hợp | **Không** | **Có** |
| Đổi provider | Khó | Dễ |

Điểm quan trọng nhất là hàng thứ hai: với Fluent API, entity là **POCO thuần** không biết gì về EF Core — điều kiện cần cho kiến trúc mà domain không phụ thuộc hạ tầng ([Module 16](../../stage-05-senior-engineering/module-16-clean-architecture/)).

Chú ý `HasConversion()` cho enum: mặc định EF lưu enum thành `int`. Lưu chuỗi khiến database **đọc được** và không vỡ khi ai đó chèn một giá trị vào giữa enum — cùng vấn đề với bitmask ở [bài 10.8](../../stage-03-aspnet-core-backend/module-10-authentication-authorization/10.7-permission-system.mdx). Đánh đổi là tốn chỗ hơn và so sánh chậm hơn chút.

### 13.3.3 — Value converter

Value converter cho phép **domain dùng kiểu riêng** trong khi database lưu kiểu nguyên thuỷ:

```csharp
// Strongly-typed ID — khong the truyen nham CustomerId vao cho LeadId
public readonly record struct CustomerId(int Value);

builder.Property(c => c.Id)
       .HasConversion(id => id.Value, value => new CustomerId(value));
```

```csharp
// Danh sach -> JSON
builder.Property(c => c.Tags)
       .HasConversion(
           v => JsonSerializer.Serialize(v, (JsonSerializerOptions?)null),
           v => JsonSerializer.Deserialize<List<string>>(v, (JsonSerializerOptions?)null)!,
           new ValueComparer<List<string>>(
               (a, b) => a!.SequenceEqual(b!),
               v => v.Aggregate(0, (h, s) => HashCode.Combine(h, s.GetHashCode())),
               v => v.ToList()));
```

**`ValueComparer` là bắt buộc với kiểu tham chiếu có thể thay đổi.** Không có nó, EF Core so sánh **tham chiếu** — và vì `customer.Tags.Add("vip")` không đổi tham chiếu, EF **không phát hiện thay đổi** và `SaveChanges` không làm gì. Một lỗi im lặng rất khó tìm.

```csharp
// DateTime luon UTC — chan loi mui gio tu goc
builder.Property(c => c.CreatedAt)
       .HasConversion(
           v => v.ToUniversalTime(),
           v => DateTime.SpecifyKind(v, DateTimeKind.Utc));
```

Bộ chuyển đổi này giải quyết một lớp bug cả nhóm: `DateTime` đọc từ SQL Server có `Kind = Unspecified`, nên `.ToLocalTime()` cho kết quả sai. Ép `Kind = Utc` khi đọc làm mọi phép tính múi giờ đúng.

Áp cho **mọi** `DateTime` trong mô hình:

```csharp
protected override void ConfigureConventions(ModelConfigurationBuilder builder)
{
    builder.Properties<DateTime>()
           .HaveConversion<UtcDateTimeConverter>();

    builder.Properties<decimal>()
           .HavePrecision(18, 2);        // tranh mac dinh cua provider
}
```

`ConfigureConventions` (EF Core 6+) là nơi đặt quy ước toàn cục — tốt hơn nhiều so với lặp cùng một cấu hình ở mọi entity.

### 13.3.4 — Owned type cho value object

```csharp
public sealed class Address                   // khong co Id — la value object
{
    public required string Street { get; init; }
    public required string City { get; init; }
    public required string PostalCode { get; init; }
}

public class Customer
{
    public int Id { get; set; }
    public Address? BillingAddress { get; set; }
    public Address? ShippingAddress { get; set; }
}
```

```csharp
builder.OwnsOne(c => c.BillingAddress, a =>
{
    a.Property(p => p.Street).HasColumnName("BillingStreet").HasMaxLength(300);
    a.Property(p => p.City).HasColumnName("BillingCity").HasMaxLength(100);
    a.Property(p => p.PostalCode).HasColumnName("BillingPostalCode").HasMaxLength(20);
});
```

Owned type ánh xạ vào **cùng bảng** với entity chủ, nên không có JOIN nào. Domain có một kiểu `Address` rõ nghĩa; database chỉ có thêm ba cột.

Ba điều cần biết:

1. Owned type **không có identity riêng** — nó không tồn tại ngoài entity chủ.
2. Nó **luôn được nạp cùng** entity chủ; không cần `Include`.
3. Từ EF Core 8, có thể ánh xạ owned type thành **cột JSON** bằng `ToJson()` — hợp với dữ liệu lồng nhau ít khi truy vấn riêng.

### 13.3.5 — Interceptor thay vì override `SaveChanges`

```csharp
// Cach pho bien nhung han che
public override Task<int> SaveChangesAsync(CancellationToken ct = default)
{
    foreach (var entry in ChangeTracker.Entries<Customer>()) { ... }   // CHI Customer
    return base.SaveChangesAsync(ct);
}
```

Cách này phải lặp cho **mỗi** loại entity, và logic nằm trong `DbContext` nên khó test và khó tái sử dụng.

```csharp
public interface IAuditable
{
    DateTime CreatedAt { get; set; }
    DateTime UpdatedAt { get; set; }
    string? CreatedBy { get; set; }
    string? UpdatedBy { get; set; }
}

public sealed class AuditInterceptor(ICurrentUser user, TimeProvider clock)
    : SaveChangesInterceptor
{
    public override ValueTask<InterceptionResult<int>> SavingChangesAsync(
        DbContextEventData eventData, InterceptionResult<int> result, CancellationToken ct = default)
    {
        var context = eventData.Context;
        if (context is null) return base.SavingChangesAsync(eventData, result, ct);

        var now = clock.GetUtcNow().UtcDateTime;

        foreach (var entry in context.ChangeTracker.Entries<IAuditable>())
        {
            if (entry.State == EntityState.Added)
            {
                entry.Entity.CreatedAt = now;
                entry.Entity.CreatedBy = user.Id;
            }

            if (entry.State is EntityState.Added or EntityState.Modified)
            {
                entry.Entity.UpdatedAt = now;
                entry.Entity.UpdatedBy = user.Id;
            }
        }

        return base.SavingChangesAsync(eventData, result, ct);
    }
}
```

```csharp
builder.Services.AddScoped<AuditInterceptor>();

builder.Services.AddDbContext<CrmDbContext>((sp, options) =>
    options.UseSqlServer(conn)
           .AddInterceptors(sp.GetRequiredService<AuditInterceptor>()));
```

Bốn lợi ích: áp cho **mọi** entity cài `IAuditable`; tiêm được dependency như `ICurrentUser`; test được riêng; và `DbContext` giữ nguyên trách nhiệm của nó.

Chú ý `AddDbContext` với overload nhận `IServiceProvider` — đó là cách lấy service scoped vào cấu hình context mà không gọi `BuildServiceProvider()` ([bài 7.7](../../stage-02-csharp-professional/module-07-dependency-injection/7.6-program-cs-and-webapplicationbuilder.mdx)).

EF Core còn có các interceptor khác đáng biết: `DbCommandInterceptor` để log hoặc sửa SQL, `DbConnectionInterceptor` để chuyển connection theo tenant.

### 13.3.6 — Rà lại code của bạn

**Danh sách rà soát DbContext và cấu hình**

- [ ] DbContext đăng ký Scoped; ngoài request thì dùng IDbContextFactory.
- [ ] Không có Task.WhenAll nào trên cùng một DbContext.
- [ ] Không dùng BeginTransaction khi chỉ có một SaveChanges.
- [ ] Cấu hình mô hình tách theo IEntityTypeConfiguration, mỗi entity một file.
- [ ] Entity không có attribute của EF Core nếu domain phải độc lập hạ tầng.
- [ ] Enum lưu dạng chuỗi nếu cần database đọc được và an toàn khi thêm giá trị.
- [ ] Mọi value converter cho kiểu tham chiếu có thể thay đổi đều có ValueComparer.
- [ ] DateTime được ép Kind = Utc khi đọc từ database.
- [ ] decimal có precision khai rõ, không dùng mặc định của provider.
- [ ] Audit dùng SaveChangesInterceptor, không override SaveChanges.
- [ ] Quy ước toàn cục đặt trong ConfigureConventions, không lặp ở mọi entity.

## Bài tập áp dụng

1. **Thiếu `ValueComparer`.** Cấu hình value converter cho `List` **không** có `ValueComparer`, thêm một phần tử vào danh sách, gọi `SaveChanges`, và xác nhận không có `UPDATE` nào. Thêm comparer và kiểm chứng.

2. **`DateTime.Kind`.** Lưu một `DateTime` UTC vào SQL Server, đọc lại và in `Kind`. Xác nhận nó là `Unspecified`. Thêm converter và kiểm chứng.

3. **Interceptor.** Chuyển logic audit từ override `SaveChangesAsync` sang `SaveChangesInterceptor`, và viết unit test cho interceptor đó mà không cần database.

## Tự kiểm tra

### DbContext là Unit of Work nghĩa là gì?

Nó gom mọi thay đổi bạn thực hiện và ghi chúng trong một transaction khi gọi SaveChanges, nên cả nhóm thay đổi cùng thành công hoặc cùng thất bại mà bạn không cần BeginTransaction. Chỉ cần transaction tường minh khi phải gọi SaveChanges nhiều lần trong một đơn vị công việc.

### Vì sao DbContext phải là Scoped và sống ngắn?

Nó không thread-safe nên không chạy song song được, và context sống lâu gây bốn vấn đề: bộ nhớ phình, trả dữ liệu cũ từ identity map, một lỗi làm hỏng toàn bộ context, và giữ connection lâu. Ngoài phạm vi request thì dùng IDbContextFactory.

### Vì sao ưu tiên Fluent API hơn Data Annotations?

Fluent API cấu hình được mọi thứ gồm quan hệ phức tạp, index có filter và khoá phức hợp, và quan trọng nhất là nó để entity là POCO thuần không phụ thuộc EF Core, điều kiện cần cho kiến trúc mà domain độc lập với hạ tầng.

### Vì sao value converter cho kiểu tham chiếu cần ValueComparer?

Vì không có nó, EF Core so sánh theo tham chiếu, mà thêm phần tử vào một danh sách không đổi tham chiếu, nên EF không phát hiện thay đổi và SaveChanges không sinh UPDATE nào. Đó là một lỗi im lặng rất khó tìm.

### Owned type dùng khi nào?

Cho value object không có identity riêng và không tồn tại ngoài entity chủ, ví dụ địa chỉ. Nó ánh xạ vào cùng bảng nên không có JOIN, luôn được nạp cùng entity chủ, và từ EF Core 8 còn ánh xạ được thành cột JSON.

### Vì sao dùng interceptor thay vì override SaveChanges?

Interceptor áp cho mọi entity cài một interface chung thay vì phải lặp cho từng loại, tiêm được dependency như thông tin người dùng hiện tại, test được riêng, và giữ DbContext đúng trách nhiệm của nó.

## Kết luận

Ba điều đáng nhớ nhất:

1. **`DbContext` là Unit of Work, không thread-safe, và phải sống ngắn.**
2. **Value converter cho kiểu tham chiếu phải có `ValueComparer`**, nếu không thay đổi bị bỏ qua im lặng.
3. **Audit thuộc về interceptor**, không thuộc về `SaveChanges` được override.
