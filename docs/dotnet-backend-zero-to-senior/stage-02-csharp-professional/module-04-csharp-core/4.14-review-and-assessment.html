4.14 — Review and Assessment

Mục tiêu bài học​

  • Nắm được ý chính của bài và mối liên hệ với module.
  • Áp dụng được kiến thức vào bối cảnh CRM/.NET backend.
  • Sẵn sàng chuyển sang bài kế tiếp với nền tảng chắc chắn.

Nội dung bài học​

4.14.1 — Thực hành​

Bài 1: Domain model sản phẩm​

Xây dựng các class Category, Supplier, Product với quan hệ liên kết.

Yêu cầu:

  • Category: Id, Name, Description, có thể có ParentCategory
  • Supplier: Id, CompanyName, ContactEmail, Phone
  • Product: Id, Name, Price (dùng Money), Stock, liên kết đến Category và Supplier
  • Price và Stock không được âm — validate trong setter/constructor
  • Override ToString() ở mỗi class
// Gợi ý khung
public class Product : BaseEntity
{
    public string Name { get; private set; }
    public Money Price { get; private set; }
    public int Stock { get; private set; }
    public Category Category { get; private set; }
    public Supplier Supplier { get; private set; }

    public Product(string name, Money price, Category category, Supplier supplier) { /* ... */ }
    public void AdjustStock(int delta) { /* validate không xuống dưới 0 */ }
    public override string GetSummary() => /* ... */;
}

Bài 2: Interface IPriceable và IDiscountable​

Định nghĩa và áp dụng hai interface cho Product.

public interface IPriceable
{
    Money Price { get; }
    Money GetFinalPrice();
}

public interface IDiscountable
{
    decimal DiscountRate { get; }
    void ApplyDiscount(decimal rate);   // 0.0 — 1.0
}

// Product implement cả hai
public class Product : BaseEntity, IPriceable, IDiscountable
{
    /* ... */
}

// Kiểm tra: hàm sau chỉ nhận IPriceable, không quan tâm kiểu cụ thể
public static void PrintPrice(IPriceable item)
    => Console.WriteLine($"Giá cuối: {item.GetFinalPrice()}");

Bài 3 (CRM): Domain model đầy đủ​

Xây dựng domain model CRM tích hợp tất cả kiến thức trong module.

Yêu cầu:

  • BaseEntity: abstract, có Id, CreatedAt, UpdatedAt, SoftDelete(), abstract GetSummary()
  • IAuditable: interface với CreatedBy, UpdatedBy
  • INotifiable: interface với GetNotificationTarget(), Preference
  • Contact extends BaseEntity, implement IAuditable
  • Lead extends Contact, thêm Source, Status (enum), method Qualify()/Disqualify()/Convert()
  • Customer extends Contact, implement INotifiable, thêm Email, TotalSpent, AddPurchase()
  • Dùng record ContactInfo(string Email, string Phone) thay vì lưu rời
  • Dùng pattern matching để viết hàm GetPriority(Contact contact) trả về chuỗi ưu tiên

4.14.2 — Tóm tắt​

Bước tiếp theo: Module 5 — Collections, LINQ và Lambda. Bạn sẽ thao tác với danh sách Customer, lọc Lead theo điều kiện, sắp xếp và nhóm dữ liệu — nền tảng cho truy vấn database sau này.

4.14.3 — Checklist trước khi sang bài tiếp theo​

  • Bạn đã nắm được các khái niệm chính và giải thích lại được bằng ví dụ của riêng mình.
  • Bạn đã chạy hoặc mô phỏng ít nhất một ví dụ trong bài.
  • Bạn đã hoàn thành phần quiz/lab cơ bản (hoặc ít nhất tự làm lại theo trí nhớ).
  • Bạn đã ghi lại 3 ý chính: học được gì, còn vướng gì, sẽ áp dụng ở đâu trong CRM.

4.14.4 — Kiểm tra & Thực hành (100 điểm)​

4.14.5 — Bối cảnh giáo trình (mục tiêu xuyên suốt)​

Trục CRM — một mục tiêu rõ: bạn hướng tới CRM production trong From Zero → Senior .NET (Backend-first). Giáo trình ưu tiên backend, bám chuỗi API → dữ liệu → vận hành → kiến trúc phân tán, thay vì trải rộng theo hướng full-stack. Mỗi module củng cố một lớp kỹ năng trên cùng một CRM học tập bạn phát triển xuyên suốt khóa.

Chuỗi năng lựcĐóng góp vào CRM học tập
Giai đoạn 1 — FoundationĐọc hiểu yêu cầu, mô hình client–server, Git — nền collaboration khi CRM lớn dần.
Giai đoạn 2 — C# + P1Domain, OOP, LINQ, async, DI — rule nghiệp vụ & tầng ứng dụng (Inventory là bản mẫu trước CRM).
Giai đoạn 3 — ASP.NET + P2Host, routing, validation, JWT, SignalR — CRM Backend API thực tế.
Giai đoạn 4 — Data + P3SQL, EF, cache, job, container — CRM ổn định & có thể triển khai.
Giai đoạn 5 — Senior + FinalClean Architecture, event/outbox, gateway, observability, perf — CRM/ERP chịu tải & có chủ.

C# professional + Project 1 (Inventory): OOP, LINQ, async, DI — domain & rule nghiệp vụ giống tầng lõi CRM/ERP.

4.14.7 — Phần A — Quiz trắc nghiệm (20 điểm)​

Gợi ý làm bài: mỗi câu 4 điểm. Ưu tiên suy nghĩ hệ quả trên CRM (tiền, dữ liệu, đa tenant, hiệu năng, bảo mật) — không chỉ nhớ định nghĩa.

Mỗi câu 4 điểm.

  1. interface trong C# cho phép?
    A. Đa kế thừa implementation từ nhiều class B. Đa kế thừa contract (nhiều interface) + một class cơ sở C. Chỉ một interface mỗi class D. Không có ý nghĩa runtime

    Đáp án: B.

  2. record (positional) so với class thường, đặc điểm nổi bật?
    A. Luôn mutable B. Value equality mặc định (theo thành phần) C. Không thể dùng trong LINQ D. Không compile trên .NET 8

    Đáp án: B.

  3. Encapsulation đạt được chủ yếu nhờ?
    A. public mọi field B. Giới hạn truy cập + API có kiểm soát C. Chỉ dùng static D. Kế thừa 5 cấp

    Đáp án: B.

  4. Polymorphism với virtual/override xảy ra ở?
    A. Compile-time overload B. Runtime theo kiểu thực của object C. JIT chỉ trong struct D. Không hỗ trợ trong C#

    Đáp án: B.

  5. Composition over inheritance nghĩa là?
    A. Luôn dùng struct B. Ưu tiên inject hành vi thay vì cây kế thừa sâu C. Không dùng interface D. Chỉ dùng extension method

    Đáp án: B.

Lab & rubric: trong README, map từng nhóm điểm rubric sang phần CRM (Lead, Customer, Deal, Billing, Notification…) và artifact (test, log, screenshot, migration).

Ít nhất 2 interface (IRepository<T>, INotifiable, …) + 1 implementation20

4.14.9 — Phần C — Reflect & nối chuỗi (không chấm điểm)​

Viết 5–8 câu (README hoặc docs/learning-log.md):

  1. Kiến thức module / project này sẽ được tái sử dụng trực tiếp ở module hoặc project CRM nào tiếp theo? (ghi tên module / P2 / P3 / Final).
  2. Nếu bỏ qua phần lab, rủi ro lớn nhất cho CRM ở giai đoạn sau là gì?
  3. Một quyết định kỹ thuật (nhỏ) bạn sẵn sàng ghi thành ADR một đoạn sau khi làm lab.
