## 1. Khi nào *không* nên microservices?

Nếu team < 5, chưa có CI/CD ổn định, chưa có observability — **modular monolith** + bounded context rõ thường nhanh hơn.

**Dấu hiệu đã đủ “đau” để tách**:

- Scale khác nhau theo workload (notification spike vs core API).
- **Release cadence** khác nhau giữa các phần (billing compliance vs CRM UI API).
- Team sở hữu rõ ràng theo domain (Conway’s Law).

---

## 2. Service decomposition

Nguyên tắc thực dụng:

- **Tách theo subdomain** có ngôn ngữ nghiệp vụ riêng (Sales vs Billing).
- Mỗi service **sở hữu dữ liệu** của nó — không share DB trực tiếp giữa hai service (anti-pattern “rạch database”).

**Strangler fig**: tách dần từ monolith bằng façade hoặc route gateway.

---

## 3. API Gateway — YARP (ưu tiên .NET)

**YARP** (Yet Another Reverse Proxy) là thư viện .NET để cấu hình reverse proxy linh hoạt trong `Program.cs`.

Ví dụ tinh thần route:

```csharp
var builder = WebApplication.CreateBuilder(args);
builder.Services.AddReverseProxy()
    .LoadFromConfig(builder.Configuration.GetSection("ReverseProxy"));

var app = builder.Build();
app.MapReverseProxy();
app.Run();
```

`appsettings.json` khai báo cluster `sales`, `billing`, route `/api/sales/{**catch-all}` → cluster sales.

**Gateway đảm nhận**: TLS termination, auth validation chung, correlation ID, rate limit, versioning.

**Ocelot**: từng phổ biến; với .NET hiện tại team Microsoft khuyến nghị **YARP** cho greenfield.

---

## 4. Giao tiếp giữa các service

| Kiểu | Khi dùng | Lưu ý |
|------|----------|--------|
| HTTP REST | đơn giản, public API | coupling thời gian, cần timeout/circuit breaker |
| gRPC | nội bộ hiệu năng, contract rõ | versioning proto cần kỷ luật |
| Message bus | eventual consistency chấp nhận được | outbox + idempotency (Module 17) |

Tránh **chụm sync** (A→B→C→A) — dễ deadlock latency và lỗi cascade.

---

## 5. Observability — bộ ba

1. **Logs** — structured (Serilog), `traceId`/`spanId` thống nhất.
2. **Metrics** — request rate, latency p95/p99, queue depth, GC.
3. **Traces** — OpenTelemetry export Jaeger/Zipkin/Azure Monitor.

ASP.NET Core:

```csharp
builder.Services.AddOpenTelemetry()
    .WithTracing(t => t
        .AddAspNetCoreInstrumentation()
        .AddHttpClientInstrumentation());
```

Gateway forward header `traceparent` (W3C) để trace xuyên suốt.

---

## 6. Identity trong hệ phân tán

Các mô hình thường gặp:

- **JWT** do gateway validate; service tin internal network + claim.
- **Token exchange** / **BFF** nếu có SPA (ngoài phạm vi backend-first nhưng hay gặp ở CRM).

Đừng để mỗi service tự gọi DB user — cân nhắc **Identity service** hoặc shared read model nhẹ (cache) với hiểu rõ stale data.

---

## 7. Anti-pattern: distributed monolith

Triệu chứng: deploy phải “đúng thứ tự”, mọi thứ gọi nhau sync, một feature chạm 6 repo.

**Thuốc**: giảm call chain, chuyển sang event, consolidate ownership, hoặc **merge lại** một phần thành monolith module hóa.

## Bổ sung (đối chiếu roadmap.sh)

- **Dapr** — sidecar building blocks (pub/sub, state) — phù hợp polyglot, thêm complexity vận hành.
- **Steeltoe** — patterns cho Spring-style trên .NET (discovery…).
- **Orleans** — actor model + virtual grain; phù hợp stateful scale-out đặc thù, không phải default CRM.

## Liên hệ CRM

- Tách **`Identity`** (auth, consent), **`Notification`** (email/SMS adapter), **`Billing`** (payment, invoice).
- Gateway route theo **tenant** (header/subdomain) và **API version** (`/v1/`, header `Api-Version`).
- Health: `/health/ready` kiểm tra DB + broker; `/health/live` chỉ process sống.
