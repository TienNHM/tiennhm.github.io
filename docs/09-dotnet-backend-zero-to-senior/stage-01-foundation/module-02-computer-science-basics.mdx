## Cách đọc module này để không bị "ngợp"

Module này có nhiều khái niệm mạng và hệ thống. Người mới nên học theo thứ tự **từ trải nghiệm hằng ngày đến thuật ngữ kỹ thuật**:

- Bắt đầu từ việc bạn mở trình duyệt và gõ URL.
- Theo dõi request đi qua DNS, TCP, HTTPS, API, database.
- Sau đó mới quay lại ghi nhớ tên gọi (DNS resolver, TLS handshake, status code...).

### Ví dụ xuyên suốt: một lần đăng nhập CRM diễn ra thế nào

1. Bạn mở `crm.company.com` và bấm **Đăng nhập**.
2. Trình duyệt hỏi DNS để biết IP của server.
3. Trình duyệt thiết lập kết nối HTTPS để mã hóa dữ liệu.
4. Frontend gửi `POST /api/auth/login` với email/mật khẩu.
5. Backend kiểm tra thông tin, trả JWT nếu hợp lệ.
6. Từ các request sau, frontend đính kèm JWT để gọi API an toàn.

Chỉ cần nắm chắc luồng này, bạn đã có nền rất tốt để học ASP.NET Core ở giai đoạn sau.

## 1. Internet hoạt động như thế nào

### DNS và IP Address

Khi bạn gõ `https://crm.company.com` vào browser, điều đầu tiên xảy ra là tra cứu DNS:

```
Browser gõ URL
      │
      ▼
DNS Resolver (ISP hoặc 8.8.8.8)
      │  "crm.company.com là IP nào?"
      ▼
DNS Server trả về: 203.0.113.45
      │
      ▼
Browser kết nối TCP đến 203.0.113.45:443
```

- **IP Address**: Địa chỉ định danh duy nhất của mỗi máy trên Internet (ví dụ `192.168.1.1` — nội bộ, `203.0.113.45` — công khai)
- **DNS (Domain Name System)**: "Danh bạ điện thoại" của Internet — ánh xạ tên miền sang IP
- **Port**: Cổng dịch vụ trên máy chủ — HTTP dùng port `80`, HTTPS dùng port `443`, ứng dụng .NET dev thường dùng `5000`/`7000`

> **Trong CRM:** Khi team sales truy cập `crm.company.com`, DNS phân giải tên miền này ra IP của server backend ASP.NET Core — đó là điểm bắt đầu mọi request.

### TCP/IP — Giao thức truyền dữ liệu

**TCP/IP** là bộ giao thức nền tảng giúp dữ liệu đi từ máy này sang máy khác đáng tin cậy:

```
Tầng ứng dụng   : HTTP, HTTPS, WebSocket
Tầng transport  : TCP (đảm bảo thứ tự, không mất gói)
Tầng Internet   : IP (định tuyến gói tin)
Tầng vật lý     : Ethernet, Wi-Fi, cáp quang
```

- **TCP** đảm bảo dữ liệu đến đủ và đúng thứ tự — phù hợp với API
- **UDP** nhanh hơn nhưng không đảm bảo — dùng cho streaming, game realtime

## 2. Client - Server Model

### Khái niệm cơ bản

```
┌─────────────────┐         HTTP Request          ┌──────────────────┐
│                 │  ─────────────────────────►   │                  │
│     CLIENT      │                               │      SERVER      │
│  (Browser/App)  │  ◄─────────────────────────   │   (ASP.NET Core) │
│                 │         HTTP Response          │                  │
└─────────────────┘                               └──────────────────┘
```

- **Client**: Bất kỳ thứ gì *gửi request* — browser, mobile app, Postman, `curl`, ứng dụng khác
- **Server**: Máy/process *lắng nghe request và trả response* — trong khóa học này là ASP.NET Core Web API
- **API (Application Programming Interface)**: "Hợp đồng" định nghĩa client được phép hỏi gì và server sẽ trả lời thế nào

### API là cầu nối

```
┌─────────┐    API Contract     ┌───────────┐    Query    ┌──────────┐
│  React  │ ── GET /customers ─►│ ASP.NET   │ ──────────► │ Database │
│ Frontend│ ◄─ 200 JSON ────── │ Web API   │ ◄────────── │ (SQL)    │
└─────────┘                     └───────────┘             └──────────┘
```

> **Trong CRM:** Frontend React gọi `GET /api/customers` đến server ASP.NET Core. Server xử lý business logic, truy vấn database, rồi trả về danh sách khách hàng dạng JSON. Frontend không cần biết database là gì — API che đi toàn bộ chi tiết đó.

## 3. HTTP/HTTPS

### HTTP Methods

HTTP định nghĩa **method (động từ)** cho từng loại thao tác:

| Method   | Ý nghĩa               | Ví dụ trong CRM                       |
|----------|-----------------------|---------------------------------------|
| `GET`    | Lấy dữ liệu           | `GET /api/customers` — xem danh sách  |
| `POST`   | Tạo mới               | `POST /api/customers` — thêm KH mới   |
| `PUT`    | Cập nhật toàn bộ      | `PUT /api/customers/5` — sửa KH #5    |
| `PATCH`  | Cập nhật một phần     | `PATCH /api/customers/5` — đổi email  |
| `DELETE` | Xóa                   | `DELETE /api/customers/5` — xóa KH    |

### HTTP Status Codes

Server luôn trả về một **status code** 3 chữ số:

| Nhóm | Ý nghĩa     | Ví dụ quan trọng                                      |
|------|-------------|-------------------------------------------------------|
| 2xx  | Thành công  | `200 OK`, `201 Created`, `204 No Content`             |
| 3xx  | Chuyển hướng| `301 Moved Permanently`, `302 Found`                  |
| 4xx  | Lỗi client  | `400 Bad Request`, `401 Unauthorized`, `404 Not Found`, `422 Unprocessable` |
| 5xx  | Lỗi server  | `500 Internal Server Error`, `503 Service Unavailable` |

> **Trong CRM:** Khi sales nhập sai email khách hàng, API trả `422 Unprocessable Entity` kèm message giải thích. Khi chưa đăng nhập mà gọi API, server trả `401 Unauthorized`.

### HTTP Headers và Body

Một HTTP request đầy đủ trông như sau:

```
POST /api/customers HTTP/1.1
Host: crm.company.com
Content-Type: application/json
Authorization: Bearer eyJhbGciOiJIUzI1NiJ9...
Content-Length: 87

{
  "name": "Nguyen Van A",
  "email": "a@example.com",
  "phone": "0912345678"
}
```

- **Headers**: Metadata — loại content, token xác thực, ngôn ngữ...
- **Body**: Dữ liệu thực sự gửi lên (chỉ có với POST, PUT, PATCH)
- **HTTPS**: Mã hóa toàn bộ traffic bằng TLS — bắt buộc trong production để bảo vệ token và dữ liệu khách hàng

### Ví dụ thực tế: tạo khách hàng mới và xử lý lỗi

Giả sử nhân viên sales tạo khách hàng từ giao diện CRM:

1. Frontend gửi `POST /api/customers` kèm JSON.
2. Nếu dữ liệu hợp lệ, backend trả `201 Created` + `id` khách hàng mới.
3. Nếu thiếu email hoặc email sai định dạng, backend trả `422 Unprocessable Entity`.

Ví dụ response lỗi:

```json
{
  "error": "ValidationFailed",
  "message": "Email is required and must be valid.",
  "field": "email"
}
```

Nhờ vậy frontend biết hiển thị lỗi đúng ô nhập liệu thay vì báo chung chung "Đã có lỗi xảy ra".

## 4. API và JSON

### REST API là gì

**REST (Representational State Transfer)** là kiến trúc thiết kế API phổ biến nhất, dựa trên nguyên tắc:

1. **Resources qua URL**: Mỗi "tài nguyên" có URL riêng — `/customers`, `/orders`, `/contacts`
2. **Stateless**: Mỗi request độc lập, server không nhớ state từ request trước
3. **HTTP methods chuẩn**: Dùng đúng GET/POST/PUT/DELETE như đã nêu
4. **JSON response**: Trả dữ liệu dạng JSON

### JSON Format

**JSON (JavaScript Object Notation)** là định dạng trao đổi dữ liệu phổ biến nhất hiện nay:

```json
{
  "id": 42,
  "name": "Nguyen Van A",
  "email": "a@example.com",
  "isActive": true,
  "tags": ["vip", "enterprise"],
  "address": {
    "city": "Ho Chi Minh",
    "country": "Vietnam"
  },
  "createdAt": "2025-01-15T08:30:00Z"
}
```

Các kiểu dữ liệu JSON: `string`, `number`, `boolean`, `null`, `array []`, `object {}`

### Serialize và Deserialize trong C#

```csharp
using System.Text.Json;

// Class ánh xạ với JSON
public class Customer
{
    public int Id { get; set; }
    public string Name { get; set; } = "";
    public string Email { get; set; } = "";
    public bool IsActive { get; set; }
}

// Deserialize: JSON string → C# object
string json = """{"id":42,"name":"Nguyen Van A","email":"a@example.com","isActive":true}""";
Customer customer = JsonSerializer.Deserialize<Customer>(json)!;
Console.WriteLine(customer.Name); // Nguyen Van A

// Serialize: C# object → JSON string
string output = JsonSerializer.Serialize(customer);
Console.WriteLine(output);
```

> **Trong CRM:** Mỗi lần frontend gửi form "Thêm khách hàng", dữ liệu được chuyển thành JSON, gửi lên server. ASP.NET Core tự động deserialize JSON đó thành object `Customer` C# để xử lý.

## 5. Cơ sở dữ liệu là gì

### Relational Database so với NoSQL

| Đặc điểm        | Relational (SQL)              | NoSQL                          |
|-----------------|-------------------------------|--------------------------------|
| Cấu trúc        | Bảng, hàng, cột (schema cố định) | Document, key-value, graph  |
| Ví dụ           | SQL Server, PostgreSQL, MySQL | MongoDB, Redis, Elasticsearch  |
| Thích hợp       | Dữ liệu có quan hệ phức tạp   | Dữ liệu linh hoạt, scale ngang|
| Query           | SQL                           | API riêng của từng DB          |
| ACID            | Có (đảm bảo toàn vẹn)         | Tùy loại                       |

**Khóa học này dùng SQL Server** — phổ biến nhất trong hệ sinh thái .NET doanh nghiệp.

### Cấu trúc Relational Database

```
Database: CrmDb
│
├── Table: Customers
│   ├── Id (int, PRIMARY KEY)
│   ├── Name (nvarchar)
│   ├── Email (nvarchar, UNIQUE)
│   └── CreatedAt (datetime)
│
├── Table: Orders
│   ├── Id (int, PRIMARY KEY)
│   ├── CustomerId (int, FOREIGN KEY → Customers.Id)
│   ├── Amount (decimal)
│   └── Status (nvarchar)
│
└── Table: Contacts
    ├── Id (int, PRIMARY KEY)
    ├── CustomerId (int, FOREIGN KEY → Customers.Id)
    └── Phone (nvarchar)
```

### SQL Cơ bản

```sql
-- Lấy tất cả khách hàng
SELECT Id, Name, Email FROM Customers;

-- Lọc khách hàng VIP (ví dụ: orders > 10 triệu)
SELECT c.Name, SUM(o.Amount) AS TotalRevenue
FROM Customers c
JOIN Orders o ON c.Id = o.CustomerId
GROUP BY c.Name
HAVING SUM(o.Amount) > 10000000;

-- Thêm khách hàng mới
INSERT INTO Customers (Name, Email, CreatedAt)
VALUES (N'Nguyen Van A', 'a@example.com', GETDATE());

-- Cập nhật email
UPDATE Customers SET Email = 'new@example.com' WHERE Id = 42;

-- Xóa khách hàng
DELETE FROM Customers WHERE Id = 42;
```

> **Trong CRM:** Toàn bộ thông tin khách hàng, đơn hàng, lịch sử tương tác đều lưu trong SQL Server. Entity Framework Core (sẽ học ở Module 9) giúp bạn viết C# thay vì SQL thuần, nhưng hiểu SQL là bắt buộc để debug và tối ưu.

## 6. Authentication và Authorization

### Hai khái niệm cần phân biệt

```
Authentication (Xác thực)          Authorization (Phân quyền)
"Bạn là ai?"                       "Bạn được làm gì?"
──────────────────────             ──────────────────────
Login với username/password   →    Admin: xem tất cả KH
Xác minh token hợp lệ         →    Sales: chỉ xem KH của mình
```

> **Trong CRM:** Mọi nhân viên đều phải đăng nhập (Authentication). Nhưng chỉ Sales Manager mới được xóa khách hàng, còn Sales thường chỉ thêm/sửa (Authorization).

### Flow đăng nhập với JWT

**JWT (JSON Web Token)** là chuẩn phổ biến cho stateless authentication:

```
1. Client gửi: POST /auth/login
   Body: { "username": "alice", "password": "secret123" }

2. Server xác thực credentials trong DB
   Nếu đúng → tạo JWT token

3. Server trả về:
   { "token": "eyJhbGciOiJIUzI1NiJ9.eyJzdWIiOiJhbGljZSIsInJvbGUiOiJhZG1pbiJ9.SflKxw..." }

4. Client lưu token (localStorage hoặc cookie)

5. Mỗi request tiếp theo, client gửi kèm header:
   Authorization: Bearer eyJhbGciOiJIUzI1NiJ9...

6. Server decode token, biết đây là "alice" với role "admin"
   → cho phép hoặc từ chối request
```

### Cấu trúc JWT

JWT gồm 3 phần ngăn cách bởi dấu `.`:

```
Header.Payload.Signature
eyJhbGciOiJIUzI1NiJ9  .  eyJzdWIiOiJhbGljZSJ9  .  SflKxw...
(thuật toán)              (dữ liệu: user, role,      (chữ ký xác thực)
                           thời gian hết hạn)
```

Payload sau khi decode:
```json
{
  "sub": "alice",
  "role": "admin",
  "exp": 1735689600,
  "iss": "crm.company.com"
}
```

> **Trong CRM:** JWT cho phép server scale ngang (nhiều instance) mà không cần chia sẻ session — mỗi server đều có thể tự decode token mà không cần tra cứu database hay Redis. Sẽ implement chi tiết ở Module 7.

## 7. Hosting và Cloud cơ bản

### Môi trường chạy ứng dụng

```
localhost (máy dev)
│  → http://localhost:5000
│  → Chỉ bạn truy cập được
│
VPS / Dedicated Server
│  → Server thuê, bạn quản lý OS
│  → IP public, mọi người truy cập qua domain
│  → Ví dụ: DigitalOcean, Linode, Vultr
│
Cloud Platform
   → Azure, AWS, Google Cloud
   → Managed services: không cần lo OS
   → Auto-scale, high availability, monitoring tích hợp
   → Khóa học này dùng Azure (hệ sinh thái Microsoft/.NET)
```

### Các khái niệm cần biết

| Khái niệm   | Giải thích                                                          |
|-------------|---------------------------------------------------------------------|
| **Port**    | Cổng dịch vụ — ASP.NET Core mặc định `5000` (HTTP), `5001` (HTTPS) |
| **Domain**  | Tên miền thân thiện — `crm.company.com` thay vì `203.0.113.45`     |
| **SSL/TLS** | Chứng chỉ mã hóa HTTPS — Let's Encrypt (miễn phí) hoặc trả phí    |
| **Docker**  | Đóng gói app + dependencies thành container — chạy nhất quán mọi nơi |
| **CI/CD**   | Tự động build + test + deploy khi push code lên Git                 |
| **Load Balancer** | Phân phối traffic đến nhiều instance của cùng một app         |

### Deployment Flow đơn giản

```
Developer push code
        │
        ▼
GitHub Actions (CI)
├── dotnet build
├── dotnet test
└── dotnet publish
        │
        ▼
Docker image được tạo
        │
        ▼
Azure App Service (CD)
        │
        ▼
https://crm.company.com ✓
```

> **Trong CRM:** Ứng dụng CRM production chạy trên Azure App Service — bạn không cần lo cài Windows/Linux, patch bảo mật hay restart server. Azure quản lý tất cả. Sẽ học chi tiết ở Stage 5 (Module 16-18).

## 8. .NET Runtime và Ecosystem

### .NET so với .NET Framework

| Đặc điểm       | .NET Framework        | .NET (Core / 5+)               |
|----------------|-----------------------|--------------------------------|
| Ra đời         | 2002                  | .NET Core 2016 → .NET 5+ 2020  |

| Phiên bản mới  | Dừng tại 4.8          | .NET 8 LTS (hiện tại), .NET 9  |
| Nên dùng       | Legacy maintenance    | Dự án mới — dùng .NET 8+       |

**Khóa học này dùng .NET 8 LTS** — phiên bản ổn định dài hạn.

### Kiến trúc .NET Runtime

```
Mã nguồn C# (.cs)
        │
        ▼ dotnet build / csc
IL (Intermediate Language) — .dll
        │
        ▼ CLR (Common Language Runtime)
JIT Compiler → Native machine code
        │
        ▼
Thực thi trên CPU
```

- **CLR (Common Language Runtime)**: Máy ảo chạy IL code — quản lý memory (GC), threading, exception
- **BCL (Base Class Library)**: Thư viện chuẩn — `System.Collections`, `System.IO`, `System.Net.Http`...
- **SDK so với Runtime**: SDK = công cụ để build (bao gồm compiler, CLI); Runtime = môi trường chạy app (nhỏ hơn, dành cho server production)

## Tóm tắt

| Chủ đề               | Điểm mấu chốt                                                            |
|----------------------|--------------------------------------------------------------------------|
| Internet             | DNS phân giải domain → IP, TCP/IP vận chuyển data tin cậy                |
| Client-Server        | Client gửi request, Server trả response, API là hợp đồng giữa hai bên    |
| HTTP                 | Method (GET/POST/PUT/DELETE) + Status Code (2xx/4xx/5xx) + Headers/Body  |
| REST API & JSON      | URL là resource, method là hành động, JSON là ngôn ngữ trao đổi          |
| Database             | SQL Server cho CRM — table/row/column, JOIN, CRUD cơ bản                 |
| Auth                 | Authentication = xác minh danh tính; Authorization = kiểm tra quyền; JWT = token stateless |
| Hosting              | Dev → localhost; Production → Azure App Service + CI/CD                  |
| .NET Ecosystem       | .NET 8, CLR, SDK so với Runtime, NuGet, cấu trúc solution nhiều project      |

**Luồng tổng quát của CRM:**

```
User mở browser
    → DNS resolve crm.company.com → Azure IP
    → HTTPS (TLS) kết nối port 443
    → HTTP POST /auth/login → Server xác thực → JWT token
    → HTTP GET /api/customers (kèm JWT) → ASP.NET Core xử lý
    → Entity Framework query SQL Server
    → Trả JSON response → Frontend render danh sách KH
```
