# 3.2 — 1. Git là gì và tại sao cần

## Mục tiêu bài học

- Nắm được ý chính của bài và mối liên hệ với module.
- Áp dụng được kiến thức vào bối cảnh CRM/.NET backend.
- Sẵn sàng chuyển sang bài kế tiếp với nền tảng chắc chắn.

## Nội dung bài học

### 3.2.1 — Version control là gì?

Hãy tưởng tượng bạn đang xây hệ thống CRM cho một công ty với 5 developer. Tuần trước bạn vừa hoàn thành tính năng tìm kiếm khách hàng. Hôm nay một đồng nghiệp vô tình xóa mất file `CustomerService.cs`. Không có Git, bạn phải viết lại từ đầu.

Git là một **hệ thống quản lý phiên bản phân tán (Distributed Version Control System)**. Nó lưu lại toàn bộ lịch sử thay đổi của codebase, cho phép nhiều người làm việc song song mà không ghi đè lên nhau.

### 3.2.2 — Câu chuyện thực tế: Trước và sau khi dùng Git

**Không dùng Git — thực trạng phổ biến ở team nhỏ:**

```
project_v1/
project_v1_backup/
project_v2_final/
project_v2_final_FINAL/
project_v2_final_FINAL_ok/       ← ai tạo cái này?
project_v2_final_FINAL_ok_2/     ← thảm họa
```

Hệ quả: không ai biết phiên bản nào đang chạy trên production, không rollback được khi lỗi, merge code thủ công bằng copy-paste gây mất tính năng.

**Với Git:**

- Mỗi thay đổi được ghi lại với tác giả, thời gian, lý do
- Rollback về bất kỳ thời điểm nào trong vài giây
- Nhiều người làm song song trên cùng codebase
- Review code trước khi merge vào nhánh chính

### 3.2.3 — Git so với SVN so với không dùng gì

| Tiêu chí | Không có VCS | SVN | Git |
|---|---|---|---|
| Làm việc offline | Khó | Không | Có |
| Branching | Thủ công | Chậm, nặng | Nhanh, nhẹ |
| Distributed | Không | Không | Có |
| Phổ biến trong .NET | — | Có (legacy) | Chuẩn hiện tại |
