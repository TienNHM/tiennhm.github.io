# 3.9 — 7. Developer Workflow thực tế

## Mục tiêu bài học

- Nắm được ý chính của bài và mối liên hệ với module.
- Áp dụng được kiến thức vào bối cảnh CRM/.NET backend.
- Sẵn sàng chuyển sang bài kế tiếp với nền tảng chắc chắn.

## Nội dung bài học

### 3.9.1 — Vòng đời một tính năng CRM

```
[Nhận ticket Jira]
       ↓
git pull origin main
       ↓
git checkout -b feature/crm-customer-import
       ↓
[Viết code + unit test]
       ↓
git add . && git commit -m "feat(crm): add CSV customer import endpoint"
       ↓
git push origin feature/crm-customer-import
       ↓
[Mở Pull Request trên GitHub]
       ↓
[Code review — sửa theo feedback]
       ↓
[CI/CD pass — Squash merge vào main]
       ↓
[Auto deploy lên staging]
       ↓
[QA test → deploy production]
```

### 3.9.2 — `.gitignore` chuẩn cho dự án .NET

Tạo file `.gitignore` ở root project với nội dung:

```bash
# .NET build output
bin/
obj/
*.user
*.suo
.vs/

# Cấu hình môi trường cục bộ — KHÔNG được commit
appsettings.Development.json
appsettings.Local.json
*.env
.env

# Packages (NuGet sẽ restore)
packages/

# Test results
TestResults/
coverage/

# OS
.DS_Store
Thumbs.db
```

> **Quan trọng:** `appsettings.Development.json` thường chứa connection string, API key. Nếu vô tình commit file này lên GitHub public, thông tin bí mật sẽ bị lộ. Luôn kiểm tra `.gitignore` trước `git add .`.

## Bài tập áp dụng

1. Tóm tắt bài học bằng ngôn ngữ của bạn.
2. Liên hệ nội dung với một tình huống thực tế trong dự án.
3. Đề xuất một cải tiến cụ thể sau khi học bài này.

## Tự kiểm tra

- Bạn có thể giải thích lại nội dung chính trong 2 phút không?
- Bạn có ví dụ áp dụng thực tế chưa?
- Bạn biết bước tiếp theo cần học/triển khai là gì không?
