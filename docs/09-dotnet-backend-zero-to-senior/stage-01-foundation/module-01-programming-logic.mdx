## 1. Biến và Kiểu Dữ Liệu

### Biến là gì?

Hãy tưởng tượng biến như một **cái hộp có nhãn dán**. Bạn đặt tên cho hộp, cho đồ vào, và có thể lấy ra hoặc thay bằng đồ khác bất kỳ lúc nào.

Trong CRM, thông tin khách hàng — tên, email, điểm tích lũy — đều được lưu trong biến.

```csharp
// Khai báo biến kiểu số nguyên (int)
int diemTichLuy = 250;

// Kiểu chuỗi ký tự (string)
string tenKhachHang = "Nguyễn Văn A";

// Kiểu đúng/sai (bool)
bool laKhachVip = false;

// Kiểu số thực (double)
double tongChiTieu = 1_500_000.50;

// var: C# tự suy ra kiểu dựa vào giá trị bên phải
var email = "nguyenvana@email.com"; // C# hiểu đây là string
var soLanMua = 12;                  // C# hiểu đây là int
```

### Các kiểu dữ liệu thường dùng

| Kiểu | Dùng khi nào | Ví dụ |
|------|-------------|-------|
| `int` | Số nguyên không có phần thập phân | tuổi, số lần mua |
| `double` | Số thực, cần độ chính xác tương đối | giá tiền, tỉ lệ |
| `decimal` | Số thực, cần độ chính xác cao (tài chính) | giá trị hóa đơn |
| `string` | Văn bản, ký tự | tên, email, địa chỉ |
| `bool` | Đúng hoặc sai | isActive, isVip |
| `DateTime` | Ngày giờ | ngày đăng ký, ngày sinh |

```csharp
// Ví dụ thực tế: thông tin một khách hàng trong CRM
string tenKhach     = "Trần Thị B";
string email        = "tranthib@company.com";
int    tuoi         = 34;
bool   daXacThucEmail = true;
decimal tongMua     = 8_750_000m;   // 'm' chỉ định đây là decimal
DateTime ngayDangKy = DateTime.Now;

Console.WriteLine($"Khách hàng: {tenKhach}, Email xác thực: {daXacThucEmail}");
// Output: Khách hàng: Trần Thị B, Email xác thực: True
```

> **Lưu ý thực tế:** Với tiền tệ, luôn dùng `decimal` thay vì `double`. `double` có thể gây sai số nhỏ do cách máy tính lưu số nhị phân — không chấp nhận được trong ứng dụng tài chính.

## 2. Điều Kiện (Conditions)

### if / else

Điều kiện cho phép chương trình **ra quyết định**: nếu điều này đúng thì làm A, ngược lại làm B.

```csharp
int diemKhachHang = 650;

if (diemKhachHang >= 500)
{
    Console.WriteLine("Khách hàng VIP — được giảm 15%");
}
else if (diemKhachHang >= 200)
{
    Console.WriteLine("Khách hàng Bạc — được giảm 5%");
}
else
{
    Console.WriteLine("Khách hàng Thường — không có ưu đãi");
}
```

### Toán tử điều kiện (ternary)

Dùng khi muốn viết gọn một điều kiện đơn giản:

```csharp
// Cú pháp: điều_kiện ? giá_trị_nếu_đúng : giá_trị_nếu_sai
string hangKhach = diemKhachHang >= 500 ? "VIP" : "Thường";
Console.WriteLine($"Hạng: {hangKhach}");
```

### switch

Dùng khi có nhiều nhánh dựa trên cùng một biến:

```csharp
string trangThaiLead = "new"; // Trạng thái lead trong CRM

switch (trangThaiLead)
{
    case "new":
        Console.WriteLine("Lead mới — cần liên hệ trong 24 giờ");
        break;
    case "contacted":
        Console.WriteLine("Đã liên hệ — chờ phản hồi");
        break;
    case "qualified":
        Console.WriteLine("Đủ điều kiện — chuyển sang sales");
        break;
    case "lost":
        Console.WriteLine("Đã mất — lưu lý do để phân tích");
        break;
    default:
        Console.WriteLine("Trạng thái không xác định");
        break;
}
```

### switch expression (C# 8+)

Cú pháp hiện đại hơn, gọn hơn:

```csharp
string moTaTrangThai = trangThaiLead switch
{
    "new"       => "Lead mới",
    "contacted" => "Đã liên hệ",
    "qualified" => "Đủ điều kiện",
    "lost"      => "Đã mất",
    _           => "Không xác định"  // _ là default
};
Console.WriteLine(moTaTrangThai);
```

## 3. Vòng Lặp (Loops)

### for — khi biết số lần lặp

```csharp
// In danh sách 5 khách hàng được gọi điện hôm nay
for (int i = 1; i <= 5; i++)
{
    Console.WriteLine($"Gọi khách hàng thứ {i}");
}
```

### while — khi không biết trước số lần lặp

```csharp
// Nhắc nhở sales gọi lại cho đến khi khách hàng trả lời
int soLanGoi = 0;
bool daTraLoi = false;

while (!daTraLoi && soLanGoi < 3)
{
    soLanGoi++;
    Console.WriteLine($"Lần gọi thứ {soLanGoi}...");

    // Giả lập: lần thứ 3 khách mới trả lời
    if (soLanGoi == 3)
        daTraLoi = true;
}

Console.WriteLine(daTraLoi ? "Khách đã trả lời!" : "Không liên lạc được, chuyển trạng thái missed.");
```

### foreach — duyệt qua từng phần tử của danh sách

```csharp
// Duyệt danh sách email để gửi thông báo
var danhSachEmail = new List<string>
{
    "khach1@email.com",
    "khach2@email.com",
    "khach3@email.com"
};

foreach (string email in danhSachEmail)
{
    Console.WriteLine($"Đang gửi email đến: {email}");
}
```

> **Khi nào dùng cái nào?**
> - `for`: khi cần chỉ số (index) hoặc biết chính xác số lần lặp.
> - `while`: khi điều kiện dừng phụ thuộc vào runtime (kết quả I/O, input người dùng...).
> - `foreach`: khi chỉ cần đọc từng phần tử của collection — đây là cách dùng phổ biến nhất trong thực tế.

## 4. Hàm (Functions / Methods)

### Tại sao cần hàm?

Hàm là cách bạn **đặt tên cho một khối logic** để có thể tái sử dụng. Thay vì viết cùng đoạn code ở nhiều chỗ, bạn đóng gói nó vào một hàm, rồi gọi bất cứ khi nào cần.

### Cú pháp cơ bản

```csharp
// Hàm không trả về giá trị (void)
void InThongTinKhach(string ten, int diem)
{
    Console.WriteLine($"Khách: {ten} | Điểm: {diem}");
}

// Hàm có giá trị trả về
string XacDinhHangKhach(int diem)
{
    if (diem >= 500) return "VIP";
    if (diem >= 200) return "Bạc";
    return "Thường";
}

// Gọi hàm
InThongTinKhach("Lê Văn C", 320);
string hang = XacDinhHangKhach(320);
Console.WriteLine($"Hạng: {hang}"); // Output: Hạng: Bạc
```

### Tham số mặc định (default parameters)

```csharp
// Tham số có giá trị mặc định
string TaoGreeting(string ten, string loai = "Thường")
{
    return loai == "VIP"
        ? $"Xin chào quý khách VIP {ten}! Chúng tôi rất trân trọng bạn."
        : $"Xin chào {ten}!";
}

Console.WriteLine(TaoGreeting("An"));           // Dùng mặc định
Console.WriteLine(TaoGreeting("Bình", "VIP")); // Truyền tường minh
```

### Quy tắc đặt tên hàm

- Dùng **PascalCase** cho tên hàm trong C#: `TinhTongDiem`, `KiemTraVip`
- Bắt đầu bằng **động từ**: `Get`, `Calculate`, `Check`, `Send`, `Create`
- Tên hàm mô tả **chính xác** việc hàm làm — đừng viết `XuLy()` hay `HamMoi()`

```csharp
// Tốt
decimal TinhGiaTriDonHang(List<decimal> danhSachGia) { ... }
bool KiemTraEmailHopLe(string email) { ... }

// Không tốt — tên quá mơ hồ
decimal Xu_Ly(List<decimal> x) { ... }
bool Check(string s) { ... }
```

## 5. Mảng và Danh Sách (Arrays & Lists)

### Array — mảng cố định

```csharp
// Mảng 3 phần tử, không thể thêm/bớt sau khi tạo
string[] danhSachSales = { "Minh", "Hoa", "Tùng" };

Console.WriteLine(danhSachSales[0]); // Output: Minh (index bắt đầu từ 0)
Console.WriteLine($"Số sales: {danhSachSales.Length}");
```

### List\<T\> — danh sách linh hoạt

Trong thực tế, `List<T>` được dùng nhiều hơn array vì có thể thêm/xóa phần tử:

```csharp
var danhSachLead = new List<string>();

// Thêm lead mới
danhSachLead.Add("Công ty ABC");
danhSachLead.Add("Cửa hàng XYZ");
danhSachLead.Add("Startup 123");

Console.WriteLine($"Tổng số lead: {danhSachLead.Count}");

// Xóa một lead
danhSachLead.Remove("Cửa hàng XYZ");

// Kiểm tra tồn tại
bool coLead = danhSachLead.Contains("Công ty ABC"); // true

// Duyệt danh sách
foreach (string lead in danhSachLead)
{
    Console.WriteLine($"- {lead}");
}
```

### Dictionary\<K,V\> — từ điển key-value

Dùng khi cần tra cứu nhanh theo một khóa:

```csharp
// Key: mã khách hàng | Value: điểm tích lũy
var diemKhachHang = new Dictionary<string, int>
{
    { "KH001", 350 },
    { "KH002", 820 },
    { "KH003", 120 }
};

// Tra cứu
int diem = diemKhachHang["KH002"];
Console.WriteLine($"Điểm KH002: {diem}"); // Output: 820

// Thêm mới
diemKhachHang["KH004"] = 500;

// Kiểm tra key tồn tại trước khi lấy (an toàn hơn)
if (diemKhachHang.TryGetValue("KH005", out int diemKH005))
{
    Console.WriteLine($"Điểm KH005: {diemKH005}");
}
else
{
    Console.WriteLine("KH005 chưa có trong hệ thống");
}
```

## 6. Tư Duy Giải Bài Toán

Trước khi viết bất kỳ dòng code nào, hãy **hiểu rõ bài toán** và **chia nhỏ** nó ra.

### Quy trình 4 bước

**Bước 1 — Hiểu đầu vào và đầu ra**

Câu hỏi: "Tôi có gì? Tôi cần trả về gì?"

**Bước 2 — Viết pseudocode** (giả code bằng tiếng Việt)

Pseudocode là mô tả logic bằng ngôn ngữ tự nhiên, không cần cú pháp chính xác.

**Bước 3 — Chuyển pseudocode thành code thật**

**Bước 4 — Test với các trường hợp biên** (edge cases)

### Ví dụ thực tế: Phân loại lead theo doanh thu tiềm năng

**Bài toán:** Cho danh sách lead với doanh thu ước tính, phân loại thành Hot/Warm/Cold và trả về số lượng mỗi loại.

**Bước 1 — Đầu vào/ra:**
- Đầu vào: danh sách số (doanh thu ước tính của từng lead)
- Đầu ra: 3 con số (số lead Hot, Warm, Cold)

**Bước 2 — Pseudocode:**
```
đặt hot = 0, warm = 0, cold = 0
với mỗi lead trong danh sách:
    nếu doanh thu >= 100 triệu: tăng hot
    nếu doanh thu >= 20 triệu:  tăng warm
    còn lại:                     tăng cold
in kết quả
```

**Bước 3 — Code C#:**
```csharp
void PhanLoaiLead(List<decimal> doanhThuList)
{
    int hot = 0, warm = 0, cold = 0;

    foreach (decimal doanhThu in doanhThuList)
    {
        if (doanhThu >= 100_000_000m)
            hot++;
        else if (doanhThu >= 20_000_000m)
            warm++;
        else
            cold++;
    }

    Console.WriteLine($"Hot: {hot} | Warm: {warm} | Cold: {cold}");
}

// Test
var leads = new List<decimal> { 150_000_000m, 50_000_000m, 5_000_000m, 200_000_000m, 10_000_000m };
PhanLoaiLead(leads);
// Output: Hot: 2 | Warm: 1 | Cold: 2
```

**Bước 4 — Edge cases cần test:**
- Danh sách rỗng → không crash, in "Hot: 0 | Warm: 0 | Cold: 0"
- Doanh thu âm → xử lý thế nào? (CRM thực tế cần validate đầu vào)
- Doanh thu đúng bằng ngưỡng (100 triệu) → phải vào Hot

## 7. Cấu Trúc Dữ Liệu Cơ Bản và Big-O

Big-O mô tả **tốc độ tăng của thời gian chạy** khi dữ liệu lớn hơn. Bạn không cần toán học — chỉ cần hiểu trực quan.

### O(1) — Hằng số, không phụ thuộc kích thước dữ liệu

```csharp
// Tra Dictionary: dù có 10 hay 10 triệu khách hàng,
// tốc độ tra cứu đều như nhau
var diemKhach = new Dictionary<string, int> { { "KH001", 500 }, /* ... */ };
int diem = diemKhach["KH001"]; // O(1)
```

Giống như tra cứu từ điển theo chữ cái — bạn không đọc từ đầu đến cuối.

### O(n) — Tuyến tính, tỉ lệ thuận với kích thước

```csharp
// Tìm khách hàng trong danh sách không được sắp xếp:
// phải duyệt từng phần tử một
List<string> danhSach = new List<string> { "An", "Bình", "Châu", /* ... */ };
string canTim = "Châu";
foreach (string ten in danhSach) // O(n)
{
    if (ten == canTim)
    {
        Console.WriteLine("Tìm thấy!");
        break;
    }
}
```

Giống như tìm một tờ giấy trong xấp giấy chưa được sắp xếp — trung bình phải lật qua n/2 tờ.

### O(n²) — Bậc hai, cần cẩn thận với dữ liệu lớn

```csharp
// So sánh mọi cặp khách hàng để tìm duplicate email:
// vòng lặp lồng nhau → O(n²)
var emails = new List<string> { "a@x.com", "b@x.com", "a@x.com" };

for (int i = 0; i < emails.Count; i++)
{
    for (int j = i + 1; j < emails.Count; j++) // O(n²)
    {
        if (emails[i] == emails[j])
            Console.WriteLine($"Duplicate: {emails[i]}");
    }
}
// Với 1000 khách hàng: ~500,000 phép so sánh
// Với 10,000 khách hàng: ~50,000,000 phép so sánh — chậm!
```

**Cách tốt hơn (O(n)) dùng HashSet:**

```csharp
var emailDaSeen = new HashSet<string>();
foreach (string email in emails)
{
    if (!emailDaSeen.Add(email)) // Add trả về false nếu đã tồn tại
        Console.WriteLine($"Duplicate: {email}");
}
// Chỉ duyệt 1 lần, bất kể có bao nhiêu email
```

### Tóm tắt Big-O

| Ký hiệu | Tên | 100 phần tử | 10,000 phần tử |
|---------|-----|-------------|----------------|
| O(1) | Hằng số | 1 bước | 1 bước |
| O(n) | Tuyến tính | 100 bước | 10,000 bước |
| O(n²) | Bậc hai | 10,000 bước | 100,000,000 bước |

> **Quy tắc thực tế:** Tránh vòng lặp lồng nhau khi làm việc với tập dữ liệu lớn. Nếu cần tra cứu nhiều lần, dùng `Dictionary` hoặc `HashSet` thay vì `List`.

```csharp
// 2. Hàm ThemLead(string ten, decimal doanhThu)
// 3. Hàm XemTatCaLead() — in ra bảng gồm tên, doanh thu, và phân loại (Hot/Warm/Cold)
// 4. Hàm TongDoanhThu() — trả về tổng doanh thu của tất cả lead
// 5. Hàm LocTheoLoai(string loai) — trả về danh sách lead theo loại

// Tiêu chí phân loại:
// Hot:  >= 100,000,000 VND
// Warm: >= 20,000,000 VND
// Cold: < 20,000,000 VND

// Dữ liệu test:
// ("Công ty Minh Phát", 150_000_000)
// ("Startup GreenTech", 35_000_000)
// ("Hộ kinh doanh Lan", 8_000_000)
// ("Tập đoàn Bắc Nam", 500_000_000)
// ("Cửa hàng Thuận Phát", 12_000_000)
```

**Gợi ý mở rộng:** Sau khi hoàn thành, thử thêm tính năng sắp xếp lead theo doanh thu giảm dần bằng `OrderByDescending`.

## Tóm Tắt

Trong module này bạn đã học:

- **Biến và kiểu dữ liệu:** Container chứa dữ liệu với kiểu rõ ràng. Dùng `decimal` cho tiền tệ, `var` khi kiểu hiển nhiên.
- **Điều kiện:** `if/else` cho phân nhánh, `switch` khi nhiều trường hợp từ cùng biến. C# 8+ có `switch expression` gọn hơn.
- **Vòng lặp:** `foreach` cho collection, `for` khi cần index, `while` khi điều kiện dừng phụ thuộc runtime.
- **Hàm:** Đặt tên bằng PascalCase, bắt đầu bằng động từ, mỗi hàm làm một việc duy nhất.
- **Collections:** `List<T>` cho danh sách linh hoạt, `Dictionary<K,V>` cho tra cứu nhanh O(1).
- **Tư duy giải bài toán:** Hiểu đầu vào/ra → pseudocode → code → test edge cases.
- **Big-O cơ bản:** O(1) hằng số, O(n) tuyến tính, O(n²) bậc hai. Tránh vòng lặp lồng nhau với dữ liệu lớn.

Tất cả những khái niệm này sẽ xuất hiện liên tục trong các module tiếp theo khi bạn xây dựng CRM thật sự với C# và .NET.

### Phần A — Quiz trắc nghiệm (20 điểm)

> **Gợi ý làm bài:** mỗi câu **4 điểm**. Ưu tiên suy nghĩ *hệ quả trên CRM* (tiền, dữ liệu, đa tenant, hiệu năng, bảo mật) — không chỉ nhớ định nghĩa.



Mỗi câu **4 điểm**. Chọn một đáp án đúng nhất.

1. Kiểu nào **nên** dùng cho tiền tệ (giá hóa đơn CRM)?  
   A. `double` B. `float` C. `decimal` D. `int`  
   > **Đáp án:** C — `decimal` tránh sai số nhị phân của floating-point.

2. Độ phức tạp truy cập phần tử theo key trong `Dictionary<TKey,TValue>` (trung bình)?  
   A. O(n) B. O(log n) C. O(1) D. O(n²)  
   > **Đáp án:** C — tra cứu băm trung bình O(1).

3. Vòng lặp nào **phù hợp** khi cần cả **index** và phần tử của `List<T>`?  
   A. `foreach` duy nhất B. `for` với index C. `while (true)` D. `do-while` không điều kiện  
   > **Đáp án:** B — `for (int i = 0; i < list.Count; i++)`.

4. `break` trong `switch` (C# cổ điển) dùng để?  
   A. Thoát khỏi toàn bộ method B. Ngăn fall-through sang `case` kế C. Bỏ qua vòng lặp D. Throw exception  
   > **Đáp án:** B — không `break` sẽ “rơi” xuống case dưới (trừ pattern mới).

5. Big-O của hai vòng `for` lồng nhau duyệt toàn bộ ma trận `n × n`?  
   A. O(n) B. O(n log n) C. O(n²) D. O(1)  
   > **Đáp án:** C.
