# 13.15 — Review and Assessment

## Mục tiêu bài học

- Nắm được ý chính của bài và mối liên hệ với module.
- Áp dụng được kiến thức vào bối cảnh CRM/.NET backend.
- Sẵn sàng chuyển sang bài kế tiếp với nền tảng chắc chắn.

## Nội dung bài học

### 13.15.1 — Thực hành

### Bài 1: Setup EF Core cho CRM, tạo migrations, seed data

**Yêu cầu:**

1. Tạo project `CRM.Data` (class library), cài `Microsoft.EntityFrameworkCore.SqlServer` và `Microsoft.EntityFrameworkCore.Tools`
2. Định nghĩa các entity: `Customer`, `Contact`, `Lead`, `User` như Section 2
3. Tạo `CrmDbContext` với `ApplyConfigurationsFromAssembly`
4. Viết Fluent API configuration cho tất cả entity (index, length, FK constraint)
5. Chạy `dotnet ef migrations add InitialCreate`
6. Tạo migration `SeedDefaultData` để insert 1 tenant, 1 admin user và 5 customer mẫu
7. Kiểm tra bằng `dotnet ef migrations script --idempotent` — đọc SQL sinh ra

**Tiêu chí hoàn thành:** Database được tạo đúng schema, seed data có mặt, không có migration pending.

---

### Bài 2: Implement Repository + UoW, fix N+1 problem

**Yêu cầu:**

1. Implement `IRepository<T>` và `IUnitOfWork` như Section 9
2. Đăng ký DI: `services.AddScoped<IUnitOfWork, UnitOfWork>()`
3. Viết API endpoint `GET /api/customers?includeLeads=true` dùng `IUnitOfWork`
4. Bật SQL logging, gọi endpoint với `includeLeads=false` → quan sát log
5. Thêm tham số `includeLeads=true`, cố tình gây N+1 bằng cách load leads trong vòng lặp
6. Fix bằng `Include` hoặc projection, so sánh số lượng query trước/sau
7. Viết unit test cho service layer dùng `MockRepository` (không cần DB thật)

**Tiêu chí hoàn thành:** Log chứng minh giảm từ N+1 xuống 1-2 queries; test xanh.

---

### Bài 3: Multi-tenant global query filter + soft delete

**Yêu cầu:**

1. Tạo `ICurrentTenantService` và `CurrentTenantService` lấy `TenantId` từ JWT
2. Đăng ký `ICurrentTenantService` vào DI, inject vào `CrmDbContext`
3. Thêm `HasQueryFilter` kết hợp `IsDeleted` và `TenantId`
4. Seed 2 tenant với dữ liệu riêng biệt
5. Gọi API với token của Tenant A → xác nhận chỉ thấy data Tenant A
6. Implement soft delete: `DELETE /api/customers/{id}` chỉ set `IsDeleted = true`
7. Thêm endpoint `GET /api/admin/customers` dùng `IgnoreQueryFilters()` — chỉ cho admin role

**Tiêu chí hoàn thành:** Tenant isolation hoạt động đúng; soft delete không xóa dữ liệu vật lý; admin endpoint thấy toàn bộ data.

---

### 13.15.2 — Tóm tắt

| Chủ đề | Điểm chính |
|---|---|
| **DbContext** | Dùng `IEntityTypeConfiguration`, auto-timestamp trong `SaveChanges` |
| **Relationships** | Fluent API rõ ràng hơn Data Annotations; Owned Entity cho Value Object |
| **Migrations** | Code-First; script trước khi apply production; không auto-migrate prod |
| **Loading** | Mặc định `AsNoTracking`; `Include` cho eager; `Select` để tránh over-fetch |
| **N+1** | Luôn bật SQL logging; fix bằng `Include` hoặc projection; `AsSplitQuery` cho nhiều collection |
| **Performance** | `ExecuteUpdate/Delete` cho bulk; `BulkExtensions` cho import lớn; Compiled Query cho hot-path |
| **Concurrency** | `IsRowVersion()` + bắt `DbUpdateConcurrencyException`; trả `409` cho client merge |
| **Repository/UoW** | Hữu ích khi cần test; không bắt buộc nếu app đơn giản |
| **Global Filter** | Soft delete + multi-tenant filter; nhớ index `TenantId`, `IsDeleted` |

### 13.15.7 — Phần A — Quiz trắc nghiệm (20 điểm)

> **Gợi ý làm bài:** mỗi câu **4 điểm**. Ưu tiên suy nghĩ *hệ quả trên CRM* (tiền, dữ liệu, đa tenant, hiệu năng, bảo mật) — không chỉ nhớ định nghĩa.

Mỗi câu **4 điểm**.

1. `AsNoTracking` phù hợp khi?  
   A. Mọi query B. Read-only không cần change tracker C. Luôn bật cho insert D. Tắt connection pool  
   > **Đáp án:** B.

2. Global Query Filter thường dùng cho?  
   A. Tăng tốc JIT B. Soft delete / multi-tenant mặc định C. Thay thế migration D. SignalR  
   > **Đáp án:** B.

3. `DbUpdateConcurrencyException` báo hiệu?  
   A. Mất mạng B. Xung đột optimistic concurrency C. Sai connection string D. Thiếu Swagger  
   > **Đáp án:** B.

4. `Include` + nhiều collection có thể cần?  
   A. `AsSplitQuery` để tránh Cartesian explosion B. `Thread.Sleep` C. `JsonIgnore` D. `UseIIS`  
   > **Đáp án:** A.

5. Migration apply production an toàn nhất khi?  
   A. `EnsureCreated()` trên prod B. Script review + pipeline + backup C. Xóa DB nightly D. Auto migrate silent  
   > **Đáp án:** B.
