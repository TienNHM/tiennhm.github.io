## 1. Class và Object

### Khai báo class cơ bản

```csharp
// Customer.cs
namespace CRM.Domain;

public class Customer
{
    // Fields - thường private
    private string _name;
    private string _email;
    private int _loyaltyPoints;

    // Auto-property (compiler tự tạo backing field)
    public Guid Id { get; init; } = Guid.NewGuid();
    public DateTime CreatedAt { get; init; } = DateTime.UtcNow;

    // Full property với validation
    public string Name
    {
        get => _name;
        set
        {
            if (string.IsNullOrWhiteSpace(value))
                throw new ArgumentException("Tên không được trống.", nameof(value));
            _name = value.Trim();
        }
    }

    public string Email
    {
        get => _email;
        private set => _email = value?.ToLowerInvariant()
            ?? throw new ArgumentNullException(nameof(value));
    }

    public int LoyaltyPoints
    {
        get => _loyaltyPoints;
        private set => _loyaltyPoints = value >= 0 ? value : 0;
    }

    // Constructor
    public Customer(string name, string email)
    {
        Name = name ?? throw new ArgumentNullException(nameof(name));
        Email = email ?? throw new ArgumentNullException(nameof(email));
    }

    // Method
    public void AddLoyaltyPoints(int points)
    {
        if (points <= 0) throw new ArgumentOutOfRangeException(nameof(points));
        LoyaltyPoints += points;
    }

    public override string ToString() => $"Customer({Id}, {Name}, {Email})";
}
```

### Auto-property vs Full property

| Trường hợp | Nên dùng |
|---|---|
| Không cần validation, chỉ lưu/đọc | Auto-property: `public string Name { get; set; }` |
| Cần validate khi gán | Full property với backing field |
| Chỉ gán lúc khởi tạo | `{ get; init; }` (C# 9+) |
| Tính toán từ fields khác | Computed property: `get => ...` |

## 2. Encapsulation

**Nguyên tắc:** Ẩn chi tiết nội bộ, chỉ lộ ra những gì cần thiết qua API công khai rõ ràng.

### Tại sao phải ẩn state?

- Ngăn code bên ngoài đặt giá trị không hợp lệ
- Dễ thay đổi implementation bên trong mà không ảnh hưởng caller
- Tập trung logic validation một chỗ

```csharp
// BAD: public field, không kiểm soát được
public class BankAccountBad
{
    public decimal Balance;  // bất kỳ ai cũng có thể gán âm
}

// GOOD: encapsulated
public class BankAccount
{
    private decimal _balance;
    private readonly List<string> _transactions = new();

    public decimal Balance => _balance;   // read-only từ bên ngoài
    public IReadOnlyList<string> Transactions => _transactions;

    public BankAccount(decimal initialBalance)
    {
        if (initialBalance < 0)
            throw new ArgumentException("Số dư ban đầu không được âm.");
        _balance = initialBalance;
    }

    public void Deposit(decimal amount)
    {
        if (amount <= 0) throw new ArgumentException("Số tiền nạp phải > 0.");
        _balance += amount;
        _transactions.Add($"+{amount:C} lúc {DateTime.UtcNow:O}");
    }

    public void Withdraw(decimal amount)
    {
        if (amount <= 0) throw new ArgumentException("Số tiền rút phải > 0.");
        if (amount > _balance) throw new InvalidOperationException("Số dư không đủ.");
        _balance -= amount;
        _transactions.Add($"-{amount:C} lúc {DateTime.UtcNow:O}");
    }
}
```

## 3. Inheritance và Polymorphism

### Hierarchy trong CRM

```csharp
// BaseEntity.cs — lớp gốc dùng chung
public abstract class BaseEntity
{
    public Guid Id { get; init; } = Guid.NewGuid();
    public DateTime CreatedAt { get; init; } = DateTime.UtcNow;
    public DateTime? UpdatedAt { get; protected set; }

    public void MarkUpdated() => UpdatedAt = DateTime.UtcNow;
}

// Contact.cs — thực thể liên lạc chung
public class Contact : BaseEntity
{
    public string FullName { get; private set; }
    public string Phone { get; private set; }

    public Contact(string fullName, string phone)
    {
        FullName = fullName ?? throw new ArgumentNullException(nameof(fullName));
        Phone = phone ?? throw new ArgumentNullException(nameof(phone));
    }

    public virtual string GetDisplayInfo() => $"{FullName} — {Phone}";
}

// Lead.cs — tiềm năng chưa chuyển đổi
public class Lead : Contact
{
    public string Source { get; private set; }   // VD: "Facebook", "Google"
    public LeadStatus Status { get; private set; } = LeadStatus.New;

    public Lead(string fullName, string phone, string source)
        : base(fullName, phone)
    {
        Source = source ?? throw new ArgumentNullException(nameof(source));
    }

    public void Qualify() => Status = LeadStatus.Qualified;
    public void Disqualify() => Status = LeadStatus.Disqualified;

    public override string GetDisplayInfo() =>
        $"[Lead] {base.GetDisplayInfo()} | Nguồn: {Source} | TT: {Status}";
}

// Customer.cs — đã chuyển đổi thành khách hàng
public class Customer : Contact
{
    public string Email { get; private set; }
    public decimal TotalSpent { get; private set; }

    public Customer(string fullName, string phone, string email)
        : base(fullName, phone)
    {
        Email = email ?? throw new ArgumentNullException(nameof(email));
    }

    public void AddPurchase(decimal amount)
    {
        if (amount <= 0) throw new ArgumentOutOfRangeException(nameof(amount));
        TotalSpent += amount;
        MarkUpdated();
    }

    public override string GetDisplayInfo() =>
        $"[Customer] {base.GetDisplayInfo()} | Email: {Email} | Chi tiêu: {TotalSpent:C}";
}

public enum LeadStatus { New, Contacted, Qualified, Disqualified, Converted }
```

### Polymorphism trong thực tế

```csharp
var contacts = new List<Contact>
{
    new Lead("Nguyễn Văn A", "0901111111", "Facebook"),
    new Customer("Trần Thị B", "0902222222", "b@example.com"),
    new Contact("Lê Văn C", "0903333333"),
};

// Gọi GetDisplayInfo() — runtime tự chọn đúng implementation
foreach (var c in contacts)
    Console.WriteLine(c.GetDisplayInfo());
```

### Cạm bẫy kế thừa sâu

- Tránh chain kế thừa quá 2-3 cấp — khó debug, brittle
- Không override method chỉ để "bỏ qua" behavior của base — vi phạm Liskov Substitution Principle
- Khi có nhiều hành vi khác nhau, dùng **composition + interface** thay vì kế thừa tiếp

## 4. Interface

### Interface vs Abstract class

| Tiêu chí | Interface | Abstract class |
|---|---|---|
| Đa kế thừa | Có (implement nhiều) | Không (chỉ 1 base class) |
| Constructor | Không có | Có |
| Fields | Không (chỉ properties) | Có |
| Default implementation | Có (C# 8+, hạn chế dùng) | Có |
| Khi nào dùng | Định nghĩa hợp đồng hành vi | Chia sẻ code chung + ép override |

### Ví dụ interface trong CRM

```csharp
// IRepository<T>.cs — contract cho data access
public interface IRepository<T> where T : BaseEntity
{
    Task<T?> GetByIdAsync(Guid id);
    Task<IEnumerable<T>> GetAllAsync();
    Task AddAsync(T entity);
    Task UpdateAsync(T entity);
    Task DeleteAsync(Guid id);
}

// INotifiable.cs — contract cho thông báo
public interface INotifiable
{
    string GetNotificationTarget();   // VD: email hoặc số điện thoại
    NotificationPreference Preference { get; }
}

public enum NotificationPreference { Email, Sms, Both, None }

// IAuditable.cs — contract theo dõi thay đổi
public interface IAuditable
{
    DateTime CreatedAt { get; }
    DateTime? UpdatedAt { get; }
    string CreatedBy { get; }
}

// Customer implement nhiều interface
public class Customer : Contact, INotifiable, IAuditable
{
    public string Email { get; private set; }
    public decimal TotalSpent { get; private set; }
    public NotificationPreference Preference { get; private set; }
    public string CreatedBy { get; init; } = "system";

    public Customer(string fullName, string phone, string email)
        : base(fullName, phone)
    {
        Email = email ?? throw new ArgumentNullException(nameof(email));
        Preference = NotificationPreference.Email;
    }

    public string GetNotificationTarget() => Email;

    public void AddPurchase(decimal amount)
    {
        if (amount <= 0) throw new ArgumentOutOfRangeException(nameof(amount));
        TotalSpent += amount;
        MarkUpdated();
    }

    public override string GetDisplayInfo() =>
        $"[Customer] {base.GetDisplayInfo()} | Email: {Email}";
}
```

### Composition over Inheritance

```csharp
// BAD: kế thừa chỉ để tái dùng 1 method
public class PremiumCustomer : Customer { /* override mọi thứ */ }

// GOOD: composition — inject behavior
public class DiscountService
{
    public decimal Calculate(Customer customer) =>
        customer.TotalSpent > 10_000_000m ? 0.15m : 0.05m;
}
```

## 5. Abstraction

### Abstract class

Dùng khi có **hành vi chung** cần chia sẻ giữa các lớp con, đồng thời ép lớp con phải implement một số phần.

```csharp
// BaseEntity.cs — abstract, không instantiate trực tiếp
public abstract class BaseEntity
{
    public Guid Id { get; init; } = Guid.NewGuid();
    public DateTime CreatedAt { get; init; } = DateTime.UtcNow;
    public DateTime? UpdatedAt { get; protected set; }
    public bool IsDeleted { get; private set; }

    public void MarkUpdated() => UpdatedAt = DateTime.UtcNow;
    public void SoftDelete()
    {
        IsDeleted = true;
        MarkUpdated();
    }

    // Lớp con phải tự xác định cách hiển thị
    public abstract string GetSummary();
}
```

### Sealed class

Dùng khi **không muốn ai kế thừa tiếp** — cải thiện performance nhỏ và đảm bảo contract không bị thay đổi.

```csharp
public sealed class Money
{
    public decimal Amount { get; }
    public string Currency { get; }

    public Money(decimal amount, string currency)
    {
        if (amount < 0) throw new ArgumentException("Số tiền không âm.");
        Amount = amount;
        Currency = currency?.ToUpperInvariant()
            ?? throw new ArgumentNullException(nameof(currency));
    }

    public Money Add(Money other)
    {
        if (Currency != other.Currency)
            throw new InvalidOperationException("Không thể cộng hai loại tiền tệ khác nhau.");
        return new Money(Amount + other.Amount, Currency);
    }

    public override string ToString() => $"{Amount:N0} {Currency}";
}
```

## 6. Access Modifiers

| Modifier | Cùng class | Cùng assembly | Lớp con | Mọi nơi |
|---|---|---|---|---|
| `private` | Có | Không | Không | Không |
| `protected` | Có | Không | Có | Không |
| `internal` | Có | Có | Không | Không |
| `protected internal` | Có | Có | Có | Không |
| `private protected` | Có | Không | Có (cùng assembly) | Không |
| `public` | Có | Có | Có | Có |

**Best practice:**

- Mặc định dùng `private` cho fields và helper methods
- `public` chỉ cho API thực sự cần lộ ra ngoài
- Properties nên `public get` + `private set` hoặc `init`
- Dùng `internal` cho class chỉ dùng trong cùng project/library

```csharp
public class Order : BaseEntity
{
    private readonly List<OrderItem> _items = new();  // private field
    private decimal _discountRate;                     // private field

    public IReadOnlyList<OrderItem> Items => _items;   // public read-only
    public decimal Total { get; private set; }         // private set

    protected void RecalculateTotal()                  // protected: lớp con dùng được
    {
        Total = _items.Sum(i => i.SubTotal) * (1 - _discountRate);
    }

    internal void ApplyBulkDiscount(decimal rate)      // internal: chỉ trong assembly
    {
        _discountRate = rate;
        RecalculateTotal();
    }
}
```

## 7. Records và Value Objects (C# 9+)

`record` tạo immutable type với equality so sánh theo giá trị thay vì tham chiếu — lý tưởng cho value objects.

```csharp
// Record — immutable, equality theo giá trị
public record ContactInfo(string Email, string Phone)
{
    // Validation trong constructor thông qua init accessor
    public string Email { get; init; } = ValidateEmail(Email);
    public string Phone { get; init; } = Phone
        ?? throw new ArgumentNullException(nameof(Phone));

    private static string ValidateEmail(string email)
    {
        if (string.IsNullOrWhiteSpace(email) || !email.Contains('@'))
            throw new ArgumentException("Email không hợp lệ.", nameof(email));
        return email.ToLowerInvariant();
    }
}

// Record struct — stack-allocated, phù hợp khi size nhỏ
public record struct DateRange(DateTime Start, DateTime End)
{
    public int Days => (End - Start).Days;
    public bool Contains(DateTime date) => date >= Start && date <= End;
}

// Sử dụng
var info1 = new ContactInfo("a@test.com", "0901111111");
var info2 = new ContactInfo("a@test.com", "0901111111");
Console.WriteLine(info1 == info2);   // True — so sánh theo giá trị

// "With expression" — tạo bản sao với thay đổi
var updated = info1 with { Phone = "0909999999" };
```

### Khi nào dùng record?

- Value objects trong Domain-Driven Design (địa chỉ, tiền tệ, khoảng thời gian)
- DTO (Data Transfer Object) không thay đổi sau khi tạo
- Kết quả trả về từ query (read model)
- **Không dùng** cho entity có identity và vòng đời riêng

## 8. Pattern Matching (C# 8+)

### is pattern và switch expression

```csharp
// is type pattern
public static string DescribeContact(Contact contact)
{
    if (contact is Customer c)
        return $"Khách hàng: {c.FullName}, đã chi {c.TotalSpent:C}";
    if (contact is Lead l)
        return $"Lead: {l.FullName}, trạng thái: {l.Status}";
    return $"Liên hệ: {contact.FullName}";
}

// switch expression với property pattern
public static string GetLeadPriority(Lead lead) => lead.Status switch
{
    LeadStatus.Qualified                  => "Cao — liên hệ ngay",
    LeadStatus.Contacted                  => "Trung bình — theo dõi",
    LeadStatus.New                        => "Mới — chờ phân loại",
    LeadStatus.Disqualified               => "Thấp — lưu trữ",
    LeadStatus.Converted                  => "Hoàn thành",
    _                                     => "Không xác định"
};

// Property pattern — kết hợp nhiều điều kiện
public static decimal GetDiscount(Customer customer) => customer switch
{
    { TotalSpent: > 50_000_000 }  => 0.20m,
    { TotalSpent: > 10_000_000 }  => 0.15m,
    { TotalSpent: > 2_000_000  }  => 0.10m,
    _                              => 0.05m
};

// Tuple pattern
public static string ClassifyDeal(LeadStatus status, decimal dealValue) =>
    (status, dealValue) switch
    {
        (LeadStatus.Qualified, > 100_000_000) => "Enterprise Deal",
        (LeadStatus.Qualified, > 10_000_000)  => "Mid-Market Deal",
        (LeadStatus.Qualified, _)              => "SMB Deal",
        (LeadStatus.Converted, _)              => "Closed Won",
        _                                      => "Pipeline"
    };
```

## Thực hành

### Bài 1: Domain model sản phẩm

Xây dựng các class `Category`, `Supplier`, `Product` với quan hệ liên kết.

**Yêu cầu:**
- `Category`: `Id`, `Name`, `Description`, có thể có `ParentCategory`
- `Supplier`: `Id`, `CompanyName`, `ContactEmail`, `Phone`
- `Product`: `Id`, `Name`, `Price` (dùng `Money`), `Stock`, liên kết đến `Category` và `Supplier`
- `Price` và `Stock` không được âm — validate trong setter/constructor
- Override `ToString()` ở mỗi class

```csharp
// Gợi ý khung
public class Product : BaseEntity
{
    public string Name { get; private set; }
    public Money Price { get; private set; }
    public int Stock { get; private set; }
    public Category Category { get; private set; }
    public Supplier Supplier { get; private set; }

    public Product(string name, Money price, Category category, Supplier supplier) { /* ... */ }
    public void AdjustStock(int delta) { /* validate không xuống dưới 0 */ }
    public override string GetSummary() => /* ... */;
}
```

### Bài 2: Interface `IPriceable` và `IDiscountable`

Định nghĩa và áp dụng hai interface cho `Product`.

```csharp
public interface IPriceable
{
    Money Price { get; }
    Money GetFinalPrice();
}

public interface IDiscountable
{
    decimal DiscountRate { get; }
    void ApplyDiscount(decimal rate);   // 0.0 — 1.0
}

// Product implement cả hai
public class Product : BaseEntity, IPriceable, IDiscountable
{
    /* ... */
}

// Kiểm tra: hàm sau chỉ nhận IPriceable, không quan tâm kiểu cụ thể
public static void PrintPrice(IPriceable item)
    => Console.WriteLine($"Giá cuối: {item.GetFinalPrice()}");
```

### Bài 3 (CRM): Domain model đầy đủ

Xây dựng domain model CRM tích hợp tất cả kiến thức trong module.

**Yêu cầu:**
- `BaseEntity`: abstract, có `Id`, `CreatedAt`, `UpdatedAt`, `SoftDelete()`, abstract `GetSummary()`
- `IAuditable`: interface với `CreatedBy`, `UpdatedBy`
- `INotifiable`: interface với `GetNotificationTarget()`, `Preference`
- `Contact` extends `BaseEntity`, implement `IAuditable`
- `Lead` extends `Contact`, thêm `Source`, `Status` (enum), method `Qualify()`/`Disqualify()`/`Convert()`
- `Customer` extends `Contact`, implement `INotifiable`, thêm `Email`, `TotalSpent`, `AddPurchase()`
- Dùng `record ContactInfo(string Email, string Phone)` thay vì lưu rời
- Dùng pattern matching để viết hàm `GetPriority(Contact contact)` trả về chuỗi ưu tiên

## Những lỗi thường gặp

**1. Public mutable fields**
```csharp
// BAD
public class Order { public decimal Total; }

// GOOD
public class Order { public decimal Total { get; private set; } }
```

**2. God class** — một class làm quá nhiều việc
```csharp
// BAD: CustomerManager xử lý cả CRUD, email, báo cáo, discount...
public class CustomerManager { /* 1000 dòng */ }

// GOOD: tách trách nhiệm
public class CustomerService { /* chỉ business logic */ }
public class CustomerRepository { /* chỉ data access */ }
public class NotificationService { /* chỉ gửi thông báo */ }
```

**3. Kế thừa thay vì composition**
```csharp
// BAD: PremiumCustomer kế thừa Customer chỉ để thêm discount
public class PremiumCustomer : Customer { }

// GOOD: inject behavior qua service
public class DiscountPolicy { public decimal GetRate(Customer c) => ...; }
```

**4. Không dùng interface — coupling trực tiếp vào implementation**
```csharp
// BAD: phụ thuộc vào class cụ thể
public class OrderService { private SqlCustomerRepository _repo; }

// GOOD: phụ thuộc vào abstraction
public class OrderService { private IRepository<Customer> _repo; }
```

**5. Lạm dụng kế thừa sâu**

Hierarchy 4-5 cấp gần như luôn là dấu hiệu thiết kế sai. Mỗi cấp tăng thêm làm code khó đọc, khó test và dễ vỡ khi requirement thay đổi.

## Tóm tắt

| Khái niệm | Mục đích chính | Ví dụ trong CRM |
|---|---|---|
| Class & Constructor | Tạo đối tượng với trạng thái hợp lệ | `Customer`, `Lead`, `Contact` |
| Encapsulation | Kiểm soát truy cập state | `private set`, validation trong setter |
| Inheritance | Tái dùng code, mô hình hóa IS-A | `Lead : Contact`, `Customer : Contact` |
| Polymorphism | Gọi code đúng lúc runtime | `GetDisplayInfo()` override |
| Interface | Định nghĩa hợp đồng hành vi | `IRepository<T>`, `INotifiable` |
| Abstraction | Ẩn chi tiết, lộ contract | `BaseEntity`, `abstract GetSummary()` |
| Access Modifiers | Giới hạn phạm vi truy cập | `private` fields, `protected` helpers |
| Record | Value object, immutable | `ContactInfo`, `Money`, `DateRange` |
| Pattern Matching | Code phân nhánh sạch | `GetDiscount()`, `GetLeadPriority()` |

**Bước tiếp theo:** Module 5 — Collections, LINQ và Lambda. Bạn sẽ thao tác với danh sách `Customer`, lọc `Lead` theo điều kiện, sắp xếp và nhóm dữ liệu — nền tảng cho truy vấn database sau này.

### Phần A — Quiz trắc nghiệm (20 điểm)

> **Gợi ý làm bài:** mỗi câu **4 điểm**. Ưu tiên suy nghĩ *hệ quả trên CRM* (tiền, dữ liệu, đa tenant, hiệu năng, bảo mật) — không chỉ nhớ định nghĩa.



Mỗi câu **4 điểm**.

1. `interface` trong C# cho phép?  
   A. Đa kế thừa implementation từ nhiều class B. Đa kế thừa contract (nhiều interface) + một class cơ sở C. Chỉ một interface mỗi class D. Không có ý nghĩa runtime  
   > **Đáp án:** B.

2. `record` (positional) so với `class` thường, đặc điểm nổi bật?  
   A. Luôn mutable B. Value equality mặc định (theo thành phần) C. Không thể dùng trong LINQ D. Không compile trên .NET 8  
   > **Đáp án:** B.

3. Encapsulation đạt được chủ yếu nhờ?  
   A. `public` mọi field B. Giới hạn truy cập + API có kiểm soát C. Chỉ dùng `static` D. Kế thừa 5 cấp  
   > **Đáp án:** B.

4. Polymorphism với `virtual`/`override` xảy ra ở?  
   A. Compile-time overload B. Runtime theo kiểu thực của object C. JIT chỉ trong struct D. Không hỗ trợ trong C#  
   > **Đáp án:** B.

5. Composition over inheritance nghĩa là?  
   A. Luôn dùng `struct` B. Ưu tiên inject hành vi thay vì cây kế thừa sâu C. Không dùng interface D. Chỉ dùng extension method  
   > **Đáp án:** B.
