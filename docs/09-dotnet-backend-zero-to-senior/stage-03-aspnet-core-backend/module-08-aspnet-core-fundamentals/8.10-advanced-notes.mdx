# 8.11 — Mở rộng và đào sâu

<SummaryBox>
Những chủ đề ASP.NET Core nối tiếp Module 8, kèm mức độ ưu tiên. Điểm cần làm rõ trước: **Minimal API không phải phiên bản rút gọn dành cho ứng dụng nhỏ** — nó có đầy đủ filter, model binding, validation và OpenAPI, chỉ là cú pháp khác. Lựa chọn giữa nó và controller là vấn đề **tổ chức code**, không phải vấn đề năng lực. Mục dễ cấu hình sai nhất là **Kestrel**: mặc định của nó phù hợp cho phần lớn trường hợp, và chỉnh sai giới hạn thường **tạo ra** vấn đề thay vì giải quyết — đặc biệt là `MaxConcurrentConnections`, thứ hay bị đặt thấp một cách vô tình.
</SummaryBox>

## Mục tiêu bài học

Sau bài này bạn có thể:

- Chọn giữa Minimal API và controller theo tiêu chí rõ ràng.
- Dùng endpoint filter thay cho action filter.
- Biết cấu hình Kestrel nào đáng chỉnh và cái nào không.
- Bật nén phản hồi an toàn.

## Nội dung bài học

### 8.11.1 — Minimal API

**Ưu tiên cao** nếu bạn đang bắt đầu dự án mới.

```csharp
// Minimal API — gon, nhung day du tinh nang
app.MapGet("/api/leads/{id:guid}", async (
    Guid id,
    ISender sender,
    CancellationToken ct) =>
{
    var result = await sender.Send(new GetLeadQuery(new LeadId(id)), ct);
    return result.IsSuccess ? Results.Ok(result.Value) : Results.NotFound();
})
.WithName("GetLead")
.Produces<LeadDto>()
.Produces(StatusCodes.Status404NotFound)
.RequireAuthorization();
```

| | Controller | Minimal API |
|---|---|---|
| Tổ chức | Gom theo lớp | Gom theo file hoặc nhóm endpoint |
| Model binding | Đầy đủ | Đầy đủ |
| Filter | Action filter | **Endpoint filter** |
| OpenAPI | Tự suy luận nhiều hơn | Khai báo tường minh hơn |
| Hiệu năng | Rất tốt | **Nhỉnh hơn một chút** |
| Phù hợp với | Nhóm endpoint có logic chung | **Vertical slice** |

Với Minimal API, gom endpoint thành nhóm để tránh một `Program.cs` dài hàng trăm dòng:

```csharp
public static class LeadEndpoints
{
    public static void MapLeadEndpoints(this IEndpointRouteBuilder app)
    {
        var group = app.MapGroup("/api/leads")
                       .RequireAuthorization()
                       .WithTags("Leads");

        group.MapGet("/{id:guid}", GetById);
        group.MapPost("/", Create);
        group.MapPut("/{id:guid}/convert", Convert);
    }
}

// Program.cs
app.MapLeadEndpoints();
app.MapCustomerEndpoints();
```

`MapGroup` cho phép áp dụng cấu hình chung — authorization, tags, filter — cho cả nhóm, nên nó bù được phần lớn lợi thế tổ chức của controller.

Cách tổ chức này hợp tự nhiên với Vertical Slice Architecture, nơi mỗi tính năng tự chứa cả endpoint lẫn handler ([bài 16.5](../../stage-05-senior-engineering/module-16-clean-architecture/16.4-vertical-slice-architecture.mdx)).

### 8.11.2 — Endpoint filter

**Ưu tiên trung bình.** Thay cho action filter trong Minimal API.

```csharp
public sealed class ValidationFilter<T> : IEndpointFilter where T : class
{
    public async ValueTask<object?> InvokeAsync(
        EndpointFilterInvocationContext context, EndpointFilterDelegate next)
    {
        var argument = context.Arguments.OfType<T>().FirstOrDefault();
        if (argument is null) return await next(context);

        var validator = context.HttpContext.RequestServices.GetService<IValidator<T>>();
        if (validator is null) return await next(context);

        var result = await validator.ValidateAsync(argument);
        if (!result.IsValid)
            return Results.ValidationProblem(result.ToDictionary());

        return await next(context);
    }
}

// Su dung
group.MapPost("/", Create).AddEndpointFilter<ValidationFilter<CreateLeadRequest>>();
```

Endpoint filter chạy **sau** model binding và **trước** handler, nên nó thấy được tham số đã được bind — khác với middleware, vốn chỉ thấy `HttpContext` thô.

**Chọn cái nào:**

| Cần gì | Dùng |
|---|---|
| Áp dụng cho **mọi** request | Middleware |
| Cần truy cập tham số đã bind | **Endpoint filter** |
| Cần biết endpoint nhưng không cần tham số | Middleware sau `UseRouting` |

### 8.11.3 — Kestrel: cẩn thận

**Ưu tiên thấp.** Mặc định phù hợp cho phần lớn trường hợp.

```csharp
builder.WebHost.ConfigureKestrel(options =>
{
    options.Limits.MaxRequestBodySize = 30 * 1024 * 1024;      // 30 MB cho upload
    options.Limits.KeepAliveTimeout = TimeSpan.FromMinutes(2);
    options.Limits.RequestHeadersTimeout = TimeSpan.FromSeconds(30);
});
```

Ba giới hạn **đáng chỉnh** và lý do:

| Giới hạn | Mặc định | Khi nào chỉnh |
|---|---|---|
| `MaxRequestBodySize` | ~28,6 MB | Cho phép upload file lớn hơn |
| `KeepAliveTimeout` | 130 giây | Hiếm khi cần đổi |
| `MaxConcurrentConnections` | **Không giới hạn** | **Gần như không bao giờ chỉnh** |

Hàng cuối là cái bẫy: người ta hay đặt `MaxConcurrentConnections = 100` vì nghe có vẻ an toàn, nhưng nó **giới hạn số kết nối TCP**, không phải số request đồng thời. Trình duyệt giữ kết nối keep-alive, nên 100 kết nối có thể chỉ là 30 người dùng — và người thứ 31 bị từ chối.

**Cách đúng để chống quá tải** là rate limiting theo người dùng hoặc IP, không phải giới hạn kết nối:

```csharp
builder.Services.AddRateLimiter(options =>
{
    options.AddFixedWindowLimiter("api", o =>
    {
        o.PermitLimit = 100;
        o.Window = TimeSpan.FromMinutes(1);
        o.QueueLimit = 10;
    });
});
```

`QueueLimit` là chi tiết hữu ích: thay vì từ chối ngay, nó cho phép một số request chờ, làm mượt các đỉnh tải ngắn ([bài 9.7](../module-09-web-api-professional/9.6-rate-limiting.mdx)).

### 8.11.4 — Nén phản hồi

**Ưu tiên trung bình.** Giảm băng thông đáng kể cho API trả JSON lớn.

```csharp
builder.Services.AddResponseCompression(options =>
{
    options.EnableForHttps = true;                 // xem canh bao ben duoi
    options.Providers.Add<BrotliCompressionProvider>();
    options.Providers.Add<GzipCompressionProvider>();
});

app.UseResponseCompression();      // dat SOM trong pipeline
```

JSON nén rất tốt — thường giảm 70–85% kích thước.

**Cảnh báo bảo mật:** `EnableForHttps = true` mở ra khả năng tấn công BREACH, trong đó kẻ tấn công suy ra bí mật bằng cách quan sát kích thước phản hồi nén. Rủi ro chỉ thực sự đáng kể khi phản hồi chứa **cả** dữ liệu bí mật (như token CSRF) **và** dữ liệu do người dùng kiểm soát. Với API trả JSON thuần và dùng token trong header, rủi ro thấp.

Nếu hệ thống chạy sau reverse proxy hoặc CDN, **để chúng nén** — hiệu quả hơn và không tốn CPU của ứng dụng.

### 8.11.5 — Những chủ đề khác

| Chủ đề | Nội dung | Ưu tiên |
|---|---|---|
| **Output caching** | Cache phản hồi ở server | **Cao** |
| **Health checks** | Liveness và readiness | **Cao** |
| **.NET Aspire** | Điều phối nhiều thành phần khi phát triển | **Trung bình** |
| **HTTP logging** | Ghi log request và response | Trung bình |
| **Request decompression** | Nhận body đã nén từ client | Thấp |
| **gRPC** | Giao tiếp nội bộ hiệu năng cao | Thấp |

**Health checks** đáng làm ngay và thường bị làm sai: liveness không được kiểm tra database, còn readiness thì phải ([bài 18.13](../../stage-05-senior-engineering/module-18-microservices/18.12-quick-real-world-example.mdx)).

```csharp
app.MapHealthChecks("/health/live", new HealthCheckOptions { Predicate = _ => false });
app.MapHealthChecks("/health/ready", new HealthCheckOptions
{
    Predicate = c => c.Tags.Contains("ready")
});
```

**HTTP logging** hữu ích khi chẩn đoán, nhưng bật mặc định trên production sẽ ghi cả mật khẩu trong body và token trong header. Nếu bật, phải cấu hình loại trừ:

```csharp
builder.Services.AddHttpLogging(o =>
{
    o.LoggingFields = HttpLoggingFields.RequestPath | HttpLoggingFields.ResponseStatusCode;
    o.RequestHeaders.Remove("Authorization");     // KHONG ghi token
});
```

## Bài tập áp dụng

1. **Chuyển sang MapGroup.** Gom các endpoint của một controller thành một nhóm Minimal API và so sánh số dòng.

2. **Viết endpoint filter.** Cài filter validation dùng FluentValidation và áp dụng cho một nhóm endpoint.

3. **Đo nén.** Gọi một endpoint trả JSON lớn với và không có `Accept-Encoding: br`, so sánh kích thước phản hồi.

## Kết luận

Ba điều đáng nhớ nhất:

1. **Minimal API đầy đủ tính năng** — chọn nó hay controller là vấn đề tổ chức code.
2. **Mặc định của Kestrel đã tốt**; chỉnh sai giới hạn kết nối thường tạo ra vấn đề mới.
3. **Chống quá tải bằng rate limiting**, không bằng giới hạn kết nối.
