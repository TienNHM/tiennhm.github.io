# 9.12 — Mini case study

<SummaryBox>
Một thay đổi **hai ký tự** — đổi kiểu trường `customerId` từ `int` sang `string` — làm ứng dụng mobile của **12.000 người dùng** không dùng được, và không thể sửa nhanh vì ứng dụng mobile phải qua kiểm duyệt cửa hàng mất **3 ngày**. Bài học cốt lõi: **API là hợp đồng**, và với client bạn **không kiểm soát được thời điểm cập nhật** — web thì refresh là xong, mobile thì không. Bài này phân loại rõ thay đổi nào **an toàn** và thay đổi nào **phá hợp đồng**, trình bày ba chiến lược versioning, và cách phát hiện breaking change **tự động trong CI** trước khi nó tới tay người dùng.
</SummaryBox>

## Mục tiêu bài học

Sau bài này bạn có thể:

- Phân loại thay đổi an toàn và thay đổi phá hợp đồng.
- Chọn chiến lược versioning phù hợp.
- Hỗ trợ nhiều phiên bản mà không nhân đôi code.
- Phát hiện breaking change tự động trong CI.

## Nội dung bài học

### 9.12.1 — Sự cố

```csharp
// Trước
public record LeadDto(int CustomerId, string Name, decimal Value);

// Sau — đổi sang Guid cho nhất quán với phần còn lại
public record LeadDto(Guid CustomerId, string Name, decimal Value);
```

```json
// Client mobile mong doi
{ "customerId": 4821, "name": "Công ty ABC", "value": 5000000 }

// Nhận được
{ "customerId": "8f3a1b2c-...", "name": "Công ty ABC", "value": 5000000 }
```

```
14:30  Deploy
14:34  Crash report tang vot: JsonParseException tren Android va iOS
14:40  12.000 người dùng không mở được app
14:45  Rollback backend — nhưng những người đã mở app trong 15 phút đó
       vẫn có dữ liệu hỏng trong cache cục bộ
```

Web app không bị ảnh hưởng vì nó dùng JavaScript (không kiểu chặt) và người dùng chỉ cần refresh. **Mobile thì không**: bản vá phải qua kiểm duyệt cửa hàng, và kể cả sau đó người dùng phải chủ động cập nhật.

### 9.12.2 — Phân loại thay đổi

**An toàn — không phá client cũ:**

```csharp
// Thêm trường MỚI (client cũ bỏ qua trường không biết)
public record LeadDto(Guid Id, string Name, decimal Value, string? Source = null);

// Them endpoint moi
app.MapGet("/api/leads/{id}/history", ...);

// Thêm giá trị enum mới — CHỈ khi client xử lý được giá trị lạ
// Noi long rang buoc: bat buoc -> tuy chon
```

**Phá hợp đồng — client cũ gãy:**

| Thay đổi | Vì sao gãy |
|---|---|
| Xoá trường | Client đọc `null` hoặc ném lỗi |
| **Đổi kiểu trường** | Deserialize thất bại — ca này |
| Đổi tên trường | Tương đương xoá rồi thêm |
| Đổi nghĩa trường | Tệ nhất — không lỗi, chỉ **sai** |
| Thêm trường bắt buộc vào request | Client cũ gửi thiếu → 400 |
| Đổi mã trạng thái HTTP | Client xử lý nhánh sai |

Hàng **đổi nghĩa** đáng sợ nhất: đổi `Value` từ "chưa thuế" sang "đã gồm thuế" không gây lỗi nào, chỉ khiến mọi con số hiển thị sai — và có thể vài tuần sau mới có người phát hiện.

### 9.12.3 — Ba chiến lược versioning

```csharp
builder.Services.AddApiVersioning(options =>
{
    options.DefaultApiVersion = new ApiVersion(1, 0);
    options.AssumeDefaultVersionWhenUnspecified = true;
    options.ReportApiVersions = true;        // tra header api-supported-versions
    options.ApiVersionReader = ApiVersionReader.Combine(
        new UrlSegmentApiVersionReader(),
        new HeaderApiVersionReader("X-Api-Version"));
});
```

| Chiến lược | Ví dụ | Ưu | Nhược |
|---|---|---|---|
| **URL** | `/api/v1/leads` | **Rõ ràng**, dễ test, dễ cache | URL đổi khi lên phiên bản |
| **Header** | `X-Api-Version: 2` | URL ổn định | Khó thử bằng trình duyệt |
| **Media type** | `Accept: application/json;v=2` | Đúng chuẩn REST | Khó dùng nhất |

**Khuyến nghị:** dùng **URL**. Nó rõ ràng nhất khi đọc log, dễ thử bằng `curl`, và dễ định tuyến ở gateway ([bài 18.4](../../stage-05-senior-engineering/module-18-microservices/18.3-api-gateway-yarp-dotnet.mdx)).

```csharp
[ApiController]
[ApiVersion("1.0")]
[ApiVersion("2.0")]
[Route("api/v{version:apiVersion}/leads")]
public class LeadsController : ControllerBase
{
    [HttpGet("{id:guid}")]
    [MapToApiVersion("1.0")]
    public async Task<ActionResult<LeadDtoV1>> GetV1(Guid id, CancellationToken ct)
    {
        var lead = await _sender.Send(new GetLeadQuery(new LeadId(id)), ct);
        return Ok(LeadDtoV1.From(lead.Value));      // CustomerId la int
    }

    [HttpGet("{id:guid}")]
    [MapToApiVersion("2.0")]
    public async Task<ActionResult<LeadDtoV2>> GetV2(Guid id, CancellationToken ct)
    {
        var lead = await _sender.Send(new GetLeadQuery(new LeadId(id)), ct);
        return Ok(LeadDtoV2.From(lead.Value));      // CustomerId la Guid
    }
}
```

### 9.12.4 — Không nhân đôi code

Sai lầm phổ biến khi versioning: chép toàn bộ tầng service cho mỗi phiên bản.

```
SAI:
  LeadServiceV1.cs   (500 dong)
  LeadServiceV2.cs   (500 dong, khac 20 dong)
  -> sua bug phai sua hai cho
```

Cách đúng: **chỉ tầng DTO có phiên bản**, logic nghiệp vụ dùng chung.

```csharp
// Một service duy nhất, trả về model NGHIỆP VỤ
public async Task<Lead> GetAsync(LeadId id, CancellationToken ct);

// Hai DTO — chỉ khác cách TRÌNH BÀY
public record LeadDtoV1(int CustomerId, string Name, decimal Value)
{
    public static LeadDtoV1 From(Lead lead) => new(
        CustomerId: lead.LegacyCustomerId,      // giữ cột cũ để tương thích
        Name: lead.Name,
        Value: lead.Value.Amount);
}

public record LeadDtoV2(Guid CustomerId, string Name, MoneyDto Value)
{
    public static LeadDtoV2 From(Lead lead) => new(
        CustomerId: lead.CustomerId.Value,
        Name: lead.Name,
        Value: MoneyDto.From(lead.Value));
}
```

Quy tắc: **phiên bản hoá ranh giới, không phiên bản hoá logic**. Nếu bạn thấy mình chép một service, ranh giới đang bị đặt sai chỗ ([bài 16.4](../../stage-05-senior-engineering/module-16-clean-architecture/16.3-uncle-bob.mdx)).

### 9.12.5 — Phát hiện breaking change trong CI

Đây là phần có giá trị cao nhất: chặn sự cố **trước khi** nó tới production.

```yaml
- name: Sinh tai lieu OpenAPI
  run: dotnet run --project src/Crm.Api -- --generate-openapi > openapi-new.json

- name: So sánh với bản đã phát hành
  run: |
    npx @redocly/cli diff openapi-baseline.json openapi-new.json \
      --fail-on breaking
```

Công cụ so sánh hai tài liệu OpenAPI và **làm CI thất bại** nếu phát hiện thay đổi phá hợp đồng — đúng loại thay đổi trong ca này.

Bổ sung một test đọc được cho từng hợp đồng quan trọng:

```csharp
[Fact]
public async Task LeadDtoV1_GiuNguyenHopDong()
{
    var response = await _client.GetAsync("/api/v1/leads/8f3a...");
    var json = await response.Content.ReadFromJsonAsync<JsonElement>();

    // Khẳng định KIỂU, không chỉ sự tồn tại
    Assert.Equal(JsonValueKind.Number, json.GetProperty("customerId").ValueKind);
    Assert.Equal(JsonValueKind.String, json.GetProperty("name").ValueKind);
}
```

Khẳng định **kiểu** chứ không chỉ sự tồn tại — vì đó chính xác là thứ đã gãy ở ca này.

### 9.12.6 — Vòng đời một phiên bản

```
1. Phat hanh v2, GIU v1 chay song song
2. Trả header cảnh báo trên v1:
      Deprecation: true
      Sunset: Sat, 31 Dec 2026 23:59:59 GMT
      Link: </api/v2/leads>; rel="successor-version"
3. Theo dõi lưu lượng v1 theo từng client
4. Liên hệ trực tiếp những client còn dùng
5. Tắt v1 khi lưu lượng về gần 0 — VÀ đã báo trước đủ lâu
```

**Thời gian giữ phiên bản cũ** phụ thuộc loại client:

| Loại client | Thời gian tối thiểu |
|---|---|
| Web do bạn kiểm soát | Vài tuần |
| Mobile | **6–12 tháng** |
| Đối tác bên thứ ba | **12 tháng trở lên**, có thông báo bằng văn bản |

Hàng mobile là bài học của ca này: kể cả khi bạn phát hành bản vá ngay, một phần người dùng **không bao giờ** cập nhật. Giám sát lưu lượng theo phiên bản là cách duy nhất biết khi nào tắt được:

```csharp
_meter.CreateCounter<long>("api.requests")
      .Add(1, new KeyValuePair<string, object?>("version", apiVersion),
              new KeyValuePair<string, object?>("client", clientId));
```

## Kết luận

Ba điều đáng nhớ nhất:

1. **API là hợp đồng**, và với mobile bạn không kiểm soát được thời điểm client cập nhật.
2. **Phiên bản hoá DTO, không phiên bản hoá logic** — nếu không bạn sẽ chép cả tầng service.
3. **Kiểm tra breaking change trong CI** chặn được đúng lớp sự cố này.
