# 9.14 — Review and Assessment

## Mục tiêu bài học

- Nắm được ý chính của bài và mối liên hệ với module.
- Áp dụng được kiến thức vào bối cảnh CRM/.NET backend.
- Sẵn sàng chuyển sang bài kế tiếp với nền tảng chắc chắn.

## Nội dung bài học

### 9.14.1 — Thực hành

### Bài 1: Customer REST API đầy đủ CRUD với Pagination + Filter + Sort

Implement `CustomersController` với các endpoints:

- `GET /api/v1/customers` — danh sách với `CustomerFilterParams` (search, status, createdFrom/To, sortBy, sortDir, page, pageSize).
- `GET /api/v1/customers/{id}` — chi tiết một customer.
- `POST /api/v1/customers` — tạo mới, trả về `201 Created` với `Location` header.
- `PUT /api/v1/customers/{id}` — cập nhật toàn bộ.
- `PATCH /api/v1/customers/{id}` — cập nhật một phần (dùng `JsonPatchDocument` hoặc request DTO riêng).
- `DELETE /api/v1/customers/{id}` — xóa, trả về `204 No Content`.

Yêu cầu:
- Response envelope `PagedResponse<CustomerDto>` cho danh sách.
- Validation với Data Annotations hoặc FluentValidation.
- Global exception handler trả về `ProblemDetails`.
- Swagger với XML comments và `ProducesResponseType` đầy đủ.

### Bài 2: File Upload API cho Avatar và Document Attachment

Implement các endpoints:

- `POST /api/v1/customers/{id}/avatar` — upload ảnh đại diện (JPEG/PNG/WebP, max 5MB).
- `DELETE /api/v1/customers/{id}/avatar` — xóa avatar.
- `POST /api/v1/customers/{id}/documents` — upload nhiều file đính kèm (PDF, DOCX, max 20MB mỗi file).
- `GET /api/v1/customers/{id}/documents` — danh sách tài liệu.
- `GET /api/v1/customers/{id}/documents/{docId}/download` — download file với streaming.

Yêu cầu:
- Validate content type và kích thước file.
- Lưu vào thư mục `wwwroot/uploads/` với tên file an toàn (GUID-based).
- Trả về URL có thể truy cập công khai.
- (Nâng cao) Tích hợp Azure Blob Storage với `Azure.Storage.Blobs`.

### Bài 3: Integration Test với WebApplicationFactory cho Customer API

Viết test suite với `xUnit` và `WebApplicationFactory`:

- **Happy path:** tạo customer → lấy danh sách → lấy chi tiết → cập nhật → xóa.
- **Validation:** POST với email sai format, tên rỗng → expect `422`.
- **Not found:** GET/PUT/DELETE với ID không tồn tại → expect `404`.
- **Pagination:** GET với `page=2&pageSize=5`, verify `pagination.page == 2`.
- **Filter:** seed 10 customers với status `lead`, filter `?status=lead`, verify count.
- **Sort:** seed customers với tên khác nhau, sort `?sortBy=name&sortDir=asc`, verify thứ tự.

Yêu cầu:
- Dùng in-memory database, seed data trong constructor hoặc `IAsyncLifetime`.
- Mỗi test class có database riêng biệt (tránh test interference).
- Assert cả status code lẫn body response.

### 9.14.2 — Tóm tắt

| Chủ đề | Công nghệ / Pattern |
|--------|---------------------|
| REST Design | Resource URL, HTTP verbs, status codes, naming |
| Versioning | `Asp.Versioning.Mvc`, URL / Header / Query string |
| Documentation | Swashbuckle, XML comments, `ProducesResponseType`, OAuth2 |
| Pagination | Offset pagination, `PagedResponse<T>`, cursor pagination |
| Filtering/Sorting | `IQueryable`, expression-based, dynamic sort |
| File Handling | `IFormFile`, multipart, streaming download |
| Rate Limiting | `AddRateLimiter`, fixed/sliding window, token bucket |
| Caching | `[ResponseCache]`, `AddOutputCache`, cache invalidation |
| Testing | `WebApplicationFactory`, `HttpClient`, in-memory DB |
| Background | `BackgroundService`, `IHostedService`, worker service |

Module 9 hoàn thành nền tảng Web API professional. Module 10 sẽ đi sâu vào **Authentication & Authorization** với JWT, OAuth2 và policy-based access control.

### 9.14.7 — Phần A — Quiz trắc nghiệm (20 điểm)

> **Gợi ý làm bài:** mỗi câu **4 điểm**. Ưu tiên suy nghĩ *hệ quả trên CRM* (tiền, dữ liệu, đa tenant, hiệu năng, bảo mật) — không chỉ nhớ định nghĩa.

Mỗi câu **4 điểm**.

1. API versioning giúp?  
   A. Xóa client cũ B. Thay đổi contract mà không phá vỡ consumer ngay C. Tăng tốc GC D. Bắt buộc dùng SOAP  
   > **Đáp án:** B.

2. Cursor pagination thường ưu hơn offset khi?  
   A. Bảng nhỏ cố định B. Dataset lớn, insert giữa danh sách nhiều C. Luôn luôn D. Khi không có DB  
   > **Đáp án:** B (tránh skip lớn).

3. HATEOAS trong REST nghĩa là?  
   A. Chỉ JSON B. Response có link điều hướng hành động tiếp theo C. Chỉ XML D. Không liên quan API  
   > **Đáp án:** B (lý thuyết; có thể không triển khai đầy đủ).

4. Output caching khác distributed cache ở?  
   A. Giống hệt B. Output cache gắn response endpoint (thường cùng node) C. Chỉ dùng cho Blazor D. Không có trong ASP.NET Core  
   > **Đáp án:** B (tinh thần).

5. `WebApplicationFactory` dùng cho?  
   A. Deploy Azure B. Integration test in-process host C. Tạo NuGet D. Code generator  
   > **Đáp án:** B.
