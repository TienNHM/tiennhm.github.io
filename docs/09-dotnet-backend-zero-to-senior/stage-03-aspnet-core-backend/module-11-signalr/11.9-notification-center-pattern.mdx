# 11.9 — 8. Notification Center Pattern

<SummaryBox>
Trung tâm thông báo là nơi **SignalR và REST phải làm việc cùng nhau**, và ranh giới rất rõ: **database là nguồn sự thật, SignalR chỉ là lớp tăng tốc**. Thứ tự luôn là **ghi trước, push sau** — vì client offline thì push mất, còn bản ghi thì còn. Hai vấn đề thực tế mà mẫu này phải giải: **chống trùng lặp**, khi một thông báo tới cả qua push lẫn qua lần đồng bộ REST kế tiếp — giải bằng cách khử trùng theo `Id` ở client; và **đồng bộ trạng thái đã đọc giữa các thiết bị**, vì đánh dấu đã đọc trên điện thoại phải làm badge trên laptop giảm theo.
</SummaryBox>

## Mục tiêu bài học

Sau bài này bạn có thể:

- Thiết kế mô hình dữ liệu cho thông báo.
- Kết hợp push và REST mà không trùng lặp.
- Đồng bộ trạng thái đã đọc giữa nhiều thiết bị.
- Gom nhóm thông báo để không làm phiền người dùng.
- Dọn dẹp dữ liệu thông báo.

## Nội dung bài học

### 11.9.1 — Mô hình dữ liệu

```csharp
public sealed class Notification
{
    public Guid Id { get; init; } = Guid.CreateVersion7();   // sap xep theo thoi gian
    public required string UserId { get; init; }
    public required NotificationType Type { get; init; }
    public required string Message { get; init; }

    public string? EntityType { get; init; }
    public string? EntityId { get; init; }
    public string? ActionUrl { get; init; }

    public DateTime CreatedAt { get; init; } = DateTime.UtcNow;
    public DateTime? ReadAt { get; set; }

    // Gom nhom: "3 nguoi da binh luan"
    public string? GroupKey { get; init; }
    public int Count { get; set; } = 1;
}
```

```csharp
modelBuilder.Entity<Notification>(e =>
{
    e.HasIndex(n => new { n.UserId, n.CreatedAt }).IsDescending(false, true);
    e.HasIndex(n => new { n.UserId, n.ReadAt });
    e.HasIndex(n => new { n.UserId, n.GroupKey });
});
```

`Guid.CreateVersion7()` (.NET 9) sinh GUID **sắp xếp được theo thời gian** — tránh phân mảnh index mà GUID ngẫu nhiên gây ra khi làm khoá chính. Với .NET cũ hơn, dùng `bigint` tự tăng hoặc thư viện sinh ULID.

`ReadAt` là `DateTime?` thay vì `bool IsRead`: nó cho bạn **cả hai** thông tin — đã đọc chưa, và đọc lúc nào — mà không tốn thêm cột.

Index đầu tiên phục vụ truy vấn chính "thông báo của tôi, mới nhất trước"; index thứ hai phục vụ đếm chưa đọc.

### 11.9.2 — Ghi trước, push sau

```csharp
public sealed class NotificationService(
    AppDbContext db,
    INotificationPublisher publisher,
    ILogger<NotificationService> logger)
{
    public async Task<NotificationDto> SendAsync(
        CreateNotificationRequest request, CancellationToken ct)
    {
        // 1. Gom nhom neu da co thong bao tuong tu chua doc
        if (request.GroupKey is not null)
        {
            var existing = await db.Notifications.FirstOrDefaultAsync(
                n => n.UserId == request.UserId
                  && n.GroupKey == request.GroupKey
                  && n.ReadAt == null, ct);

            if (existing is not null)
            {
                existing.Count++;
                await db.SaveChangesAsync(ct);

                var updated = existing.ToDto();
                await publisher.PublishAsync(request.UserId, updated, ct);
                return updated;
            }
        }

        // 2. Tao moi va LUU truoc
        var notification = new Notification { ... };
        db.Notifications.Add(notification);
        await db.SaveChangesAsync(ct);

        // 3. Push sau khi da luu
        var dto = notification.ToDto();
        await publisher.PublishAsync(request.UserId, dto, ct);

        return dto;
    }
}
```

Thứ tự này là bắt buộc ([bài 11.8](11.8-ihubcontext-server-push-outside-hub.mdx)): client offline thì push mất, nhưng bản ghi vẫn còn và họ thấy khi mở lại ứng dụng.

`INotificationPublisher` là interface hẹp bọc `IHubContext`, nên `NotificationService` test được mà không cần SignalR.

**Gom nhóm** ở bước 1 giải quyết một vấn đề thật: 50 người thích bài viết của bạn không nên là 50 thông báo. `GroupKey` kiểu `"post:{id}:like"` cho phép gộp thành "50 người đã thích bài viết của bạn".

### 11.9.3 — API đồng bộ

```csharp
[ApiController]
[Route("api/v1/notifications")]
[Authorize]
public sealed class NotificationsController(
    AppDbContext db, ICurrentUser user) : ControllerBase
{
    [HttpGet]
    public async Task<ActionResult<PagedResponse<NotificationDto>>> GetAll(
        [FromQuery] DateTime? since,
        [FromQuery] bool unreadOnly = false,
        [FromQuery] int limit = 20,
        CancellationToken ct = default)
    {
        var query = db.Notifications.AsNoTracking()
            .Where(n => n.UserId == user.Id);

        if (since is { } s)      query = query.Where(n => n.CreatedAt > s);
        if (unreadOnly)          query = query.Where(n => n.ReadAt == null);

        var items = await query
            .OrderByDescending(n => n.CreatedAt).ThenByDescending(n => n.Id)
            .Take(Math.Min(limit, 100))
            .Select(n => n.ToDto())
            .ToListAsync(ct);

        return Ok(items);
    }

    [HttpGet("unread-count")]
    public async Task<ActionResult<int>> GetUnreadCount(CancellationToken ct)
        => Ok(await db.Notifications
            .CountAsync(n => n.UserId == user.Id && n.ReadAt == null, ct));

    [HttpPost("{id:guid}/read")]
    public async Task<IActionResult> MarkAsRead(Guid id, CancellationToken ct)
    {
        var affected = await db.Notifications
            .Where(n => n.Id == id && n.UserId == user.Id && n.ReadAt == null)
            .ExecuteUpdateAsync(s => s.SetProperty(n => n.ReadAt, DateTime.UtcNow), ct);

        if (affected == 0) return NotFound();

        // Bao cho CAC THIET BI KHAC cua chinh nguoi do
        await _publisher.PublishReadStateAsync(user.Id, id, ct);
        return NoContent();
    }
}
```

Ba chi tiết:

**`since` là tham số then chốt** — nó cho client lấy đúng những gì đã bỏ lỡ sau khi kết nối lại ([bài 11.5](11.5-client-side-integration.mdx)), thay vì tải lại toàn bộ.

**`ExecuteUpdateAsync`** cập nhật thẳng bằng một câu `UPDATE`, không nạp entity. Điều kiện `n.UserId == user.Id` vừa là phân quyền vừa là bộ lọc — không ai đánh dấu đọc thông báo của người khác ([bài 10.7](../module-10-authentication-authorization/10.7-resource-based-authorization.mdx)).

**Push lại trạng thái đã đọc.** Người dùng đọc trên điện thoại thì badge trên laptop phải giảm theo. Đây là chi tiết nhỏ mà thiếu nó thì trải nghiệm trông hỏng.

### 11.9.4 — Chống trùng lặp ở client

Một thông báo có thể tới **hai lần**: qua push, và qua lần đồng bộ REST kế tiếp. Khử trùng theo `Id`:

```typescript
class NotificationStore {
  private readonly seen = new Set<string>();
  private items: NotificationDto[] = [];

  add(notification: NotificationDto): boolean {
    if (this.seen.has(notification.id)) return false;    // da co

    this.seen.add(notification.id);
    this.items = [notification, ...this.items];
    return true;
  }

  markRead(id: string): void {
    const item = this.items.find(n => n.id === id);
    if (item && !item.readAt) {
      item.readAt = new Date().toISOString();
      this.unreadCount--;
    }
  }
}
```

Client đăng ký **cả hai** nguồn vào cùng một store:

```typescript
hub.on("ReceiveNotification", n => store.add(n));
hub.on("NotificationRead", ({ id }) => store.markRead(id));

connection.onreconnected(async () => {
  const missed = await api.getNotifications({ since: store.lastCreatedAt });
  missed.forEach(n => store.add(n));      // trung thi bi bo qua
});
```

`markRead` kiểm tra `!item.readAt` trước khi giảm bộ đếm — nếu không, đánh dấu đọc hai lần (một từ hành động của chính mình, một từ push của thiết bị khác) sẽ làm bộ đếm âm.

`Set` này lớn dần theo phiên. Với ứng dụng chạy nhiều giờ, giới hạn kích thước hoặc chỉ giữ `Id` của N thông báo gần nhất.

### 11.9.5 — Dọn dẹp

Bảng thông báo phình rất nhanh — 1.000 người dùng × 20 thông báo mỗi ngày là 600.000 bản ghi mỗi tháng.

```csharp
public sealed class NotificationCleanupWorker(
    IServiceScopeFactory scopeFactory,
    ILogger<NotificationCleanupWorker> logger) : BackgroundService
{
    protected override async Task ExecuteAsync(CancellationToken ct)
    {
        using var timer = new PeriodicTimer(TimeSpan.FromHours(24));

        while (await timer.WaitForNextTickAsync(ct))
        {
            try
            {
                await using var scope = scopeFactory.CreateAsyncScope();
                var db = scope.ServiceProvider.GetRequiredService<AppDbContext>();

                // Da doc + qua 30 ngay
                var readCutoff = DateTime.UtcNow.AddDays(-30);
                var removed = await db.Notifications
                    .Where(n => n.ReadAt != null && n.ReadAt < readCutoff)
                    .ExecuteDeleteAsync(ct);

                // Chua doc nhung qua 90 ngay — khong ai doc nua
                var staleCutoff = DateTime.UtcNow.AddDays(-90);
                removed += await db.Notifications
                    .Where(n => n.ReadAt == null && n.CreatedAt < staleCutoff)
                    .ExecuteDeleteAsync(ct);

                logger.LogInformation("Da xoa {Count} thong bao cu", removed);
            }
            catch (Exception ex)
            {
                logger.LogError(ex, "Don dep thong bao that bai");
            }
        }
    }
}
```

Hai mốc khác nhau có chủ đích: đã đọc thì xoá sớm, chưa đọc thì giữ lâu hơn — nhưng vẫn phải xoá, vì thông báo 3 tháng tuổi không còn ý nghĩa.

Nhớ khoá phân tán nếu chạy nhiều instance ([bài 9.10](../module-09-web-api-professional/9.10-hosted-service-background-jobs.mdx)), và `ExecuteDeleteAsync` trên bảng lớn nên chia lô để không giữ khoá quá lâu.

## Bài tập áp dụng

1. **Trùng lặp.** Đẩy một thông báo qua push **và** để nó xuất hiện trong lần đồng bộ REST kế tiếp. Xác nhận client hiển thị **hai** lần. Thêm khử trùng theo `Id` và kiểm chứng.

2. **Bộ đếm âm.** Đánh dấu đã đọc từ hai thiết bị gần như đồng thời và xác nhận bộ đếm chưa đọc xuống dưới 0. Thêm kiểm tra `!item.readAt` và kiểm chứng.

3. **Gom nhóm.** Sinh 50 thông báo cùng `GroupKey` và xác nhận chỉ một bản ghi tồn tại với `Count = 50`. Đo số dòng trong database so với khi không gom.

## Kết luận

Ba điều đáng nhớ nhất:

1. **Database là nguồn sự thật, push là lớp tăng tốc.** Ghi trước, push sau.
2. **Khử trùng lặp theo `Id`** — push và đồng bộ REST sẽ chồng lên nhau.
3. **Đẩy cả trạng thái đã đọc** để badge đồng bộ giữa các thiết bị.
