# 11.11 — 10. Scale-out và Production

## Mục tiêu bài học

- Nắm được ý chính của bài và mối liên hệ với module.
- Áp dụng được kiến thức vào bối cảnh CRM/.NET backend.
- Sẵn sàng chuyển sang bài kế tiếp với nền tảng chắc chắn.

## Nội dung bài học

### Vấn đề với nhiều instance

```
[Client A] ─── Instance 1 ───┐
                              ├─── Backplane (Redis) ──── broadcast tới tất cả
[Client B] ─── Instance 2 ───┘
```

Khi Instance 1 muốn gửi cho Client B (đang kết nối Instance 2), cần có backplane để relay message.

### Redis Backplane

```bash
dotnet add package Microsoft.AspNetCore.SignalR.StackExchangeRedis
```

```csharp
// Program.cs
builder.Services.AddSignalR()
    .AddStackExchangeRedis(
        builder.Configuration.GetConnectionString("Redis")!,
        options =>
        {
            options.Configuration.ChannelPrefix = RedisChannel.Literal("crm");
        });
```

### Azure SignalR Service (Managed)

```bash
dotnet add package Microsoft.Azure.SignalR
```

```csharp
// Program.cs — thay AddStackExchangeRedis bằng:
builder.Services.AddSignalR()
    .AddAzureSignalR(builder.Configuration["Azure:SignalR:ConnectionString"]!);
```

Azure SignalR Service xử lý toàn bộ infrastructure: connection management, scale-out, geo-replication — không cần tự quản lý Redis.

### Sticky Session

Khi dùng Redis backplane với nginx/load balancer, cần bật **sticky session** (IP hash hoặc session cookie) để negotiate và WebSocket upgrade đều đến cùng một instance:

```nginx
upstream signalr_backend {
    ip_hash;  # Sticky session
    server api1:5000;
    server api2:5000;
}
```

### Giới hạn kết nối

| Tier | Concurrent connections |
|---|---|
| Free (Azure SignalR) | 20 |
| Standard (Azure SignalR) | 1.000/unit |
| Self-hosted (Redis backplane) | Giới hạn bởi RAM/CPU |
