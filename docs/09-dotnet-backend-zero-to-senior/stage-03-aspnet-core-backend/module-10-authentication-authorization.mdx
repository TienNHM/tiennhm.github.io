## 1. Authentication vs Authorization

### Phân biệt

| | Authentication (Xác thực) | Authorization (Phân quyền) |
|---|---|---|
| Câu hỏi | "Bạn là ai?" | "Bạn được làm gì?" |
| Kết quả | ClaimsPrincipal với danh tính | Cho phép hoặc từ chối hành động |
| Ví dụ CRM | Login bằng email/password | SalesRep chỉ sửa customer của mình |

### Flow tổng quan

```
Client → [POST /auth/login] → Server xác thực → trả JWT
Client → [GET /customers] + Bearer <token> → Middleware validate JWT → tạo ClaimsPrincipal → Authorization Policy kiểm tra → Controller
```

### ClaimsPrincipal, ClaimsIdentity, Claim

```csharp
// Claim: một đơn vị thông tin về user
var claim = new Claim(ClaimTypes.Name, "nguyen.van.a@crm.com");
var roleClaim = new Claim(ClaimTypes.Role, "SalesRep");
var customClaim = new Claim("territory", "HCM");

// ClaimsIdentity: tập hợp claims + authentication scheme
var identity = new ClaimsIdentity(
    new[] { claim, roleClaim, customClaim },
    authenticationType: "Bearer"
);

// ClaimsPrincipal: có thể có nhiều identity
var principal = new ClaimsPrincipal(identity);

// Truy cập trong controller
string? userId = User.FindFirstValue(ClaimTypes.NameIdentifier);
bool isAdmin = User.IsInRole("Admin");
string? territory = User.FindFirstValue("territory");
```

## 2. JWT Authentication

### Cấu trúc JWT

JWT gồm 3 phần ngăn cách bởi dấu chấm: `header.payload.signature`

```
eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9   ← Header (Base64Url)
.eyJzdWIiOiIxMjMiLCJlbWFpbCI6ImFAYi5jb20iLCJyb2xlIjoiU2FsZXNSZXAiLCJleHAiOjE3MTk4MDAwMDB9
.SflKxwRJSMeKKF2QT4fwpMeJf36POk6yJV_adQssw5c  ← Signature (HMAC-SHA256)
```

**Payload thường dùng trong CRM:**

```json
{
  "sub": "user-guid-here",
  "email": "a.nguyen@crm.com",
  "role": "SalesRep",
  "territory": "HCM",
  "permissions": ["customer.read", "deal.create"],
  "exp": 1719800000,
  "iss": "crm-api",
  "aud": "crm-client"
}
```

### Cấu hình trong Program.cs

```csharp
// appsettings.json
// "Jwt": {
//   "SecretKey": "your-256-bit-secret-key-here-minimum-32-chars",
//   "Issuer": "crm-api",
//   "Audience": "crm-client",
//   "ExpiryMinutes": 15
// }

builder.Services.AddAuthentication(options =>
{
    options.DefaultAuthenticateScheme = JwtBearerDefaults.AuthenticationScheme;
    options.DefaultChallengeScheme    = JwtBearerDefaults.AuthenticationScheme;
})
.AddJwtBearer(options =>
{
    var jwtSettings = builder.Configuration.GetSection("Jwt");
    var key = Encoding.UTF8.GetBytes(jwtSettings["SecretKey"]!);

    options.TokenValidationParameters = new TokenValidationParameters
    {
        ValidateIssuer           = true,
        ValidIssuer              = jwtSettings["Issuer"],
        ValidateAudience         = true,
        ValidAudience            = jwtSettings["Audience"],
        ValidateIssuerSigningKey = true,
        IssuerSigningKey         = new SymmetricSecurityKey(key),
        ValidateLifetime         = true,
        ClockSkew                = TimeSpan.Zero  // không cho phép trễ
    };
});

builder.Services.AddAuthorization();
// ...
app.UseAuthentication();
app.UseAuthorization();
```

### Token Generation Service

```csharp
public interface ITokenService
{
    string GenerateAccessToken(AppUser user, IList<string> roles);
    string GenerateRefreshToken();
}

public class TokenService : ITokenService
{
    private readonly IConfiguration _config;

    public TokenService(IConfiguration config) => _config = config;

    public string GenerateAccessToken(AppUser user, IList<string> roles)
    {
        var jwtSettings = _config.GetSection("Jwt");
        var key = new SymmetricSecurityKey(
            Encoding.UTF8.GetBytes(jwtSettings["SecretKey"]!));

        var claims = new List<Claim>
        {
            new(ClaimTypes.NameIdentifier, user.Id),
            new(ClaimTypes.Email, user.Email!),
            new("territory", user.Territory ?? string.Empty),
        };

        // Thêm roles vào claims
        foreach (var role in roles)
            claims.Add(new Claim(ClaimTypes.Role, role));

        var token = new JwtSecurityToken(
            issuer:   jwtSettings["Issuer"],
            audience: jwtSettings["Audience"],
            claims:   claims,
            expires:  DateTime.UtcNow.AddMinutes(
                          double.Parse(jwtSettings["ExpiryMinutes"]!)),
            signingCredentials: new SigningCredentials(
                          key, SecurityAlgorithms.HmacSha256)
        );

        return new JwtSecurityTokenHandler().WriteToken(token);
    }

    public string GenerateRefreshToken()
    {
        var bytes = RandomNumberGenerator.GetBytes(64);
        return Convert.ToBase64String(bytes);
    }
}
```

### LoginController

```csharp
[ApiController]
[Route("api/auth")]
public class AuthController : ControllerBase
{
    private readonly UserManager<AppUser> _userManager;
    private readonly ITokenService _tokenService;
    private readonly AppDbContext _db;

    public AuthController(UserManager<AppUser> um,
                          ITokenService ts, AppDbContext db)
    {
        _userManager  = um;
        _tokenService = ts;
        _db           = db;
    }

    [HttpPost("login")]
    public async Task<IActionResult> Login([FromBody] LoginRequest req)
    {
        var user = await _userManager.FindByEmailAsync(req.Email);
        if (user is null || !await _userManager.CheckPasswordAsync(user, req.Password))
            return Unauthorized(new { message = "Email hoặc mật khẩu không đúng." });

        var roles        = await _userManager.GetRolesAsync(user);
        var accessToken  = _tokenService.GenerateAccessToken(user, roles);
        var refreshToken = _tokenService.GenerateRefreshToken();

        // Lưu refresh token
        _db.RefreshTokens.Add(new RefreshToken
        {
            Token      = refreshToken,
            UserId     = user.Id,
            ExpiresAt  = DateTime.UtcNow.AddDays(7),
            CreatedAt  = DateTime.UtcNow,
            IsRevoked  = false
        });
        await _db.SaveChangesAsync();

        return Ok(new { accessToken, refreshToken });
    }
}
```

## 3. Refresh Token

### Tại sao cần Refresh Token?

Access token có TTL ngắn (5–15 phút) để giảm nguy cơ khi bị đánh cắp. Refresh token (TTL 7–30 ngày) cho phép client lấy access token mới mà không cần đăng nhập lại.

### Schema bảng RefreshTokens

```sql
CREATE TABLE RefreshTokens (
    Id          UNIQUEIDENTIFIER PRIMARY KEY DEFAULT NEWID(),
    Token       NVARCHAR(256) NOT NULL UNIQUE,
    UserId      NVARCHAR(450) NOT NULL,      -- FK → AspNetUsers.Id
    ExpiresAt   DATETIME2 NOT NULL,
    CreatedAt   DATETIME2 NOT NULL,
    RevokedAt   DATETIME2 NULL,
    ReplacedBy  NVARCHAR(256) NULL,          -- token mới sau rotation
    IsRevoked   BIT NOT NULL DEFAULT 0
);
```

### Rotation Strategy và Revocation

```csharp
[HttpPost("refresh")]
public async Task<IActionResult> Refresh([FromBody] RefreshRequest req)
{
    var existing = await _db.RefreshTokens
        .Include(r => r.User)
        .FirstOrDefaultAsync(r => r.Token == req.RefreshToken);

    if (existing is null || existing.IsRevoked || existing.ExpiresAt < DateTime.UtcNow)
        return Unauthorized(new { message = "Refresh token không hợp lệ hoặc đã hết hạn." });

    // Revoke token cũ
    existing.IsRevoked = true;
    existing.RevokedAt = DateTime.UtcNow;

    // Tạo token mới
    var roles       = await _userManager.GetRolesAsync(existing.User);
    var newAccess   = _tokenService.GenerateAccessToken(existing.User, roles);
    var newRefresh  = _tokenService.GenerateRefreshToken();

    existing.ReplacedBy = newRefresh;

    _db.RefreshTokens.Add(new RefreshToken
    {
        Token     = newRefresh,
        UserId    = existing.UserId,
        ExpiresAt = DateTime.UtcNow.AddDays(7),
        CreatedAt = DateTime.UtcNow,
        IsRevoked = false
    });

    await _db.SaveChangesAsync();
    return Ok(new { accessToken = newAccess, refreshToken = newRefresh });
}

[HttpPost("logout")]
[Authorize]
public async Task<IActionResult> Logout([FromBody] RefreshRequest req)
{
    var token = await _db.RefreshTokens
        .FirstOrDefaultAsync(r => r.Token == req.RefreshToken);

    if (token is not null)
    {
        token.IsRevoked = true;
        token.RevokedAt = DateTime.UtcNow;
        await _db.SaveChangesAsync();
    }
    return NoContent();
}
```

## 5. Policy-based Authorization

### Cấu hình Policies

```csharp
builder.Services.AddAuthorization(options =>
{
    // Chỉ SalesRep và Manager mới truy cập customer pipeline
    options.AddPolicy("CanAccessPipeline", policy =>
        policy.RequireRole(CrmRoles.SalesRep, CrmRoles.Manager));

    // Chỉ Manager/Admin mới approve deal
    options.AddPolicy("CanApproveDeal", policy =>
        policy.RequireRole(CrmRoles.Admin, CrmRoles.Manager));

    // Yêu cầu claim territory tồn tại
    options.AddPolicy("HasTerritory", policy =>
        policy.RequireClaim("territory"));
});
```

### Custom Requirement

```csharp
// Requirement: deal value >= threshold
public class MinDealValueRequirement : IAuthorizationRequirement
{
    public decimal Threshold { get; }
    public MinDealValueRequirement(decimal threshold) => Threshold = threshold;
}

public class MinDealValueHandler
    : AuthorizationHandler<MinDealValueRequirement, Deal>
{
    protected override Task HandleRequirementAsync(
        AuthorizationHandlerContext context,
        MinDealValueRequirement requirement,
        Deal deal)
    {
        bool isApprover = context.User.IsInRole(CrmRoles.Admin)
                       || context.User.IsInRole(CrmRoles.Manager);

        if (isApprover && deal.Value >= requirement.Threshold)
            context.Succeed(requirement);

        return Task.CompletedTask;
    }
}

// Đăng ký
builder.Services.AddSingleton<IAuthorizationHandler, MinDealValueHandler>();
builder.Services.AddAuthorization(options =>
{
    options.AddPolicy("ApproveBigDeal", policy =>
        policy.AddRequirements(new MinDealValueRequirement(500_000_000m))); // 500 triệu VND
});
```

## 6. Resource-based Authorization

Dùng khi quyết định phân quyền phụ thuộc vào dữ liệu thực tế của resource.

### Requirement + Handler

```csharp
public class SameOwnerRequirement : IAuthorizationRequirement { }

public class CustomerOwnerHandler
    : AuthorizationHandler<SameOwnerRequirement, Customer>
{
    protected override Task HandleRequirementAsync(
        AuthorizationHandlerContext context,
        SameOwnerRequirement requirement,
        Customer customer)
    {
        var userId = context.User.FindFirstValue(ClaimTypes.NameIdentifier);

        if (context.User.IsInRole(CrmRoles.Admin)
            || context.User.IsInRole(CrmRoles.Manager)
            || customer.OwnerId == userId)
        {
            context.Succeed(requirement);
        }

        return Task.CompletedTask;
    }
}
```

### Sử dụng trong Controller

```csharp
[Authorize]
[HttpPut("customers/{id}")]
public async Task<IActionResult> UpdateCustomer(
    Guid id,
    [FromBody] UpdateCustomerRequest req,
    [FromServices] IAuthorizationService authService)
{
    var customer = await _db.Customers.FindAsync(id);
    if (customer is null) return NotFound();

    var result = await authService.AuthorizeAsync(
        User, customer, new SameOwnerRequirement());

    if (!result.Succeeded)
        return Forbid();

    // ... cập nhật
    return NoContent();
}
```

### Territory-based cho Manager

```csharp
public class TerritoryDealHandler
    : AuthorizationHandler<SameOwnerRequirement, Deal>
{
    protected override Task HandleRequirementAsync(
        AuthorizationHandlerContext context,
        SameOwnerRequirement requirement,
        Deal deal)
    {
        var territory = context.User.FindFirstValue("territory");

        if (context.User.IsInRole(CrmRoles.Admin)
            || deal.Territory == territory
            || deal.OwnerId == context.User.FindFirstValue(ClaimTypes.NameIdentifier))
        {
            context.Succeed(requirement);
        }

        return Task.CompletedTask;
    }
}
```

## 7. Permission System

Khi roles không đủ chi tiết, dùng permission table để kiểm soát từng hành động.

### Permission Enum

```csharp
[Flags]
public enum Permission : long
{
    None              = 0,
    CustomerRead      = 1 << 0,
    CustomerCreate    = 1 << 1,
    CustomerUpdate    = 1 << 2,
    CustomerDelete    = 1 << 3,
    DealRead          = 1 << 4,
    DealCreate        = 1 << 5,
    DealApprove       = 1 << 6,
    ReportView        = 1 << 7,
    UserManage        = 1 << 8,
}
```

### Lưu trữ và Load Permissions

```csharp
// Bảng UserPermissions (EF Core)
public class UserPermission
{
    public string UserId    { get; set; } = default!;
    public Permission Value { get; set; }
}

// Thêm permissions vào JWT claims khi login
var permissionValue = await _db.UserPermissions
    .Where(up => up.UserId == user.Id)
    .Select(up => up.Value)
    .FirstOrDefaultAsync();

claims.Add(new Claim("permissions", ((long)permissionValue).ToString()));
```

### PermissionRequirement và Handler

```csharp
public class PermissionRequirement : IAuthorizationRequirement
{
    public Permission Permission { get; }
    public PermissionRequirement(Permission permission) => Permission = permission;
}

public class PermissionHandler : AuthorizationHandler<PermissionRequirement>
{
    protected override Task HandleRequirementAsync(
        AuthorizationHandlerContext context,
        PermissionRequirement requirement)
    {
        var permClaim = context.User.FindFirstValue("permissions");
        if (permClaim is not null && long.TryParse(permClaim, out var permValue))
        {
            var userPerms = (Permission)permValue;
            if (userPerms.HasFlag(requirement.Permission))
                context.Succeed(requirement);
        }
        return Task.CompletedTask;
    }
}

// Đăng ký
builder.Services.AddSingleton<IAuthorizationHandler, PermissionHandler>();
builder.Services.AddAuthorization(options =>
{
    options.AddPolicy("CanApproveDeal",
        p => p.AddRequirements(new PermissionRequirement(Permission.DealApprove)));
    options.AddPolicy("CanManageUsers",
        p => p.AddRequirements(new PermissionRequirement(Permission.UserManage)));
});
```

### Attribute Helper

```csharp

[HttpPost("deals/{id}/approve")]
```

## 8. ASP.NET Core Identity (Overview)

### Khi nào dùng Identity vs tự xây

| Tình huống | Lựa chọn |
|---|---|
| Cần nhanh, có sẵn password hashing, lockout, 2FA | ASP.NET Core Identity |
| Tích hợp với hệ thống user cũ / LDAP / custom DB | Tự xây `UserManager` logic |
| Module này | JWT-first, dùng Identity chỉ để hash password + UserManager |

### Tích hợp tối thiểu

```csharp
// Program.cs
builder.Services.AddIdentityCore<AppUser>(opt =>
{
    opt.Password.RequireDigit           = true;
    opt.Password.RequiredLength         = 8;
    opt.Lockout.MaxFailedAccessAttempts = 5;
    opt.Lockout.DefaultLockoutTimeSpan  = TimeSpan.FromMinutes(15);
})
.AddRoles<IdentityRole>()
.AddEntityFrameworkStores<AppDbContext>();

// AppUser mở rộng IdentityUser
public class AppUser : IdentityUser
{
    public string? FullName  { get; set; }
    public string? Territory { get; set; }
}
```

> **Lưu ý:** Module này không dùng `AddDefaultIdentity` (vốn kéo theo cookie authentication). Chỉ dùng `AddIdentityCore` + JWT Bearer.

## 9. External Login và OAuth2 (Overview)

### Concept

User click "Đăng nhập bằng Google" → redirect sang Google → Google trả về `code` → server đổi `code` lấy `id_token` → tạo/map user trong DB → phát JWT nội bộ.

### Cấu hình Google Login

```csharp
builder.Services.AddAuthentication()
    .AddGoogle(options =>
    {
        options.ClientId     = builder.Configuration["Google:ClientId"]!;
        options.ClientSecret = builder.Configuration["Google:ClientSecret"]!;
        options.CallbackPath = "/api/auth/google/callback";
    });
```

### Lưu ExternalLogin

```csharp
// Kiểm tra hoặc tạo user khi callback
var info = await _signInManager.GetExternalLoginInfoAsync();
var result = await _signInManager.ExternalLoginSignInAsync(
    info.LoginProvider, info.ProviderKey, isPersistent: false);

if (!result.Succeeded)
{
    // Tạo user mới, liên kết external login
    var user = new AppUser { Email = email, UserName = email };
    await _userManager.CreateAsync(user);
    await _userManager.AddLoginAsync(user, info);

// Phát JWT nội bộ như bình thường

```

## 10. Security Best Practices

```csharp
// 1. KHÔNG log password hoặc token
// BAD:
_logger.LogInformation("User login: {email} {password}", email, password);
// GOOD:
_logger.LogInformation("User login attempt: {email}", email);

// 2. Validate signing key đủ độ dài (>= 256 bits = 32 bytes)
if (Encoding.UTF8.GetByteCount(secretKey) < 32)
    throw new InvalidOperationException("JWT SecretKey phải >= 32 ký tự.");

// 3. HTTPS only — trong Production
app.UseHttpsRedirection();
// Kết hợp HSTS
app.UseHsts();

// 4. Audit log đăng nhập/đăng xuất
public async Task LogAudit(string userId, string action, string detail)
{
    _db.AuditLogs.Add(new AuditLog
    {
        UserId    = userId,
        Action    = action,
        Detail    = detail,
        Timestamp = DateTime.UtcNow,
        IpAddress = _httpContextAccessor.HttpContext?.Connection.RemoteIpAddress?.ToString()
    });
    await _db.SaveChangesAsync();
}

// 5. Brute force protection — dùng lockout của Identity
// (đã cấu hình ở phần Identity: MaxFailedAccessAttempts = 5)

// 6. Rotate JWT secret key định kỳ, lưu trong Azure Key Vault / AWS Secrets Manager
// Đừng hardcode trong appsettings.json khi deploy Production
```

**Checklist bảo mật tối thiểu:**

- [ ] JWT SecretKey >= 32 ký tự, lưu trong secret manager
- [ ] `ClockSkew = TimeSpan.Zero` để không cho phép token hết hạn nhưng vẫn được chấp nhận
- [ ] Refresh token stored hashed (không plain text) nếu DB bị lộ
- [ ] HTTPS enforced ở cả load balancer lẫn app layer
- [ ] Log tất cả login/logout/failed attempts với IP
- [ ] Revoke all refresh tokens khi user đổi mật khẩu

## Thực hành

### Bài 1 — Implement JWT Auth cho CRM

**Yêu cầu:** Xây dựng 3 endpoint: `POST /api/auth/register`, `POST /api/auth/login`, `POST /api/auth/refresh`.

**Hướng dẫn:**

1. Tạo `AppUser : IdentityUser` với thêm field `Territory`, `FullName`.
2. Implement `TokenService` (xem mục 2).
3. `RegisterRequest` validate email, password >= 8 ký tự; trả `201 Created`.
4. `LoginRequest` trả `{ accessToken, refreshToken, expiresIn }`.
5. `RefreshRequest` nhận `refreshToken`, kiểm tra DB, rotation, trả token mới.
6. Viết unit test cho `TokenService.GenerateAccessToken`.

**Kiểm tra:** Dùng Postman gọi login → lấy token → gọi `GET /api/customers` với Bearer token.

---

### Bài 2 — Policy-based Authorization: SalesRep chỉ truy cập Customer của mình

**Yêu cầu:** `PUT /api/customers/{id}` — SalesRep chỉ được update customer mà `OwnerId == userId`. Manager/Admin được update tất cả.

**Hướng dẫn:**

1. Thêm `OwnerId` vào bảng `Customers`.
2. Implement `SameOwnerRequirement` và `CustomerOwnerHandler` (xem mục 6).
3. Đăng ký handler, inject `IAuthorizationService` vào controller.
4. Trong `UpdateCustomer`: load customer → `AuthorizeAsync(User, customer, new SameOwnerRequirement())` → nếu fail trả `403 Forbidden`.
5. Viết integration test: tạo 2 user (SalesRep A, SalesRep B), login A cố update customer của B → expect 403.

---

### Bài 3 — Fine-grained Permission System

**Yêu cầu:** Implement `Permission` enum + middleware, kiểm soát hành động `DealApprove`.

**Hướng dẫn:**

1. Tạo `Permission` enum (xem mục 7), bảng `UserPermissions`.
2. Seed dữ liệu: Admin có tất cả permissions, SalesRep có `CustomerRead | CustomerCreate | DealRead | DealCreate`.
3. Khi login, load permission từ DB, đưa vào claim `"permissions"`.
4. Implement `PermissionHandler`, đăng ký policy `"CanApproveDeal"`.
5. `POST /api/deals/{id}/approve` dùng `[Authorize(Policy = "CanApproveDeal")]`.
6. Test: SalesRep gọi endpoint approve → 403; Manager (được gán `DealApprove`) → 200.

## Tóm tắt

| Chủ đề | Khi nào dùng |
|---|---|
| JWT Bearer | Xác thực stateless cho API |
| Refresh Token | Duy trì session dài hạn mà không cần login lại |
| Role-based | Phân quyền theo nhóm đơn giản (Admin, SalesRep...) |
| Policy-based | Logic phức tạp hơn: có thể combine nhiều điều kiện |
| Resource-based | Phân quyền dựa vào dữ liệu của resource cụ thể |
| Permission System | Fine-grained control khi role không đủ chi tiết |
| Identity | Quản lý user, password hashing, lockout |
| External Login | SSO với Google/Microsoft |

Nguyên tắc cốt lõi: **xác thực trước, phân quyền sau, least privilege — mỗi user chỉ có đúng những gì họ cần.**

Mỗi câu **4 điểm**.

1. JWT **signature** dùng để?  
   A. Nén payload B. Đảm bảo toàn vẹn (và issuer) nếu secret/keys đúng C. Mã hóa ẩn payload D. Thay session server  
   > **Đáp án:** B — payload Base64 **không** phải mã hóa bí mật; cần hiểu JWE nếu encrypt.

   A. Giống nhau B. Policy gom nhiều rule/requirement linh hoạt hơn “chỉ role” C. Policy không dùng được trên API D. Role không tồn tại trong .NET

3. Refresh token pattern nhằm?  
   A. Tăng kích thước cookie B. Giảm rủi ro khi access token TTL ngắn C. Xóa HTTPS D. Thay thế password hash  
   > **Đáp án:** B.

4. OWASP khuyến nghị với JWT ở browser?

   > **Đáp án:** B (tinh thần; backend-first vẫn cần biết).

5. “Least privilege” nghĩa là?  
   A. Cấp tất cả quyền B. Chỉ quyền tối thiểu cần thiết C. Chỉ admin đăng nhập D. Tắt logging
